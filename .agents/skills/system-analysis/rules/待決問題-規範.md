# Rule 1 [must] - 擋住只標答案會改到它的步驟
- 一題待決問題擋住某一步,要同時符合兩點:那一步的理由欄依賴提出這題的步驟,而且這題不同的答案會改到那一步要用的東西(名稱、參數、port、路徑、時間長度、要存的欄位)
- 只符合第一點的不標;沒有任何一步被擋住時,「擋住」欄寫「—」
- 為什麼:「擋住」決定流程要不要在下一波之前停下來問使用者;漏標,下一波照 planner 的預設做法寫完,使用者改了答案就要整步重做;多標,每一波都在問與下一波無關的問題,問題又散回每一波

## good example
- S3 部署的理由欄依賴 S2 的心跳;Q2 問心跳間隔,**答案會改到反向代理的閒置逾時,標擋住 S3**;Q1 問等待中斷線保不保留座位,部署用不到,**不標**
```
| Q | 提出的步驟 | 問題與可選的做法 | 擋住 | 決定 |
|---|---|---|---|---|
| Q1 | S2 | 等待中斷線也保留座位 60 秒嗎?(a)保留(先採用)(b)立即視為離開 | — | 待決 |
| Q2 | S2 | 心跳間隔:(a)15 秒(先採用)(b)30 秒 | S3 | 待決 |
```

## bad example
- 同兩題,但 **Q1 也因為 S3 依賴 S2 就標了擋住**;流程為了一題部署根本用不到的問題,在第 2 波之前停下來
```
| Q | 提出的步驟 | 問題與可選的做法 | 擋住 | 決定 |
|---|---|---|---|---|
| Q1 | S2 | 等待中斷線也保留座位 60 秒嗎?(a)保留(先採用)(b)立即視為離開 | S3 | 待決 |
| Q2 | S2 | 心跳間隔:(a)15 秒(先採用)(b)30 秒 | S3 | 待決 |
```

## good example
- 邊界:Q3 問訂單編號的格式,看起來只是後端的事;但 **S4 資料庫的理由欄依賴 S3,編號格式會改到主鍵的長度**,所以擋住 S4
```
| Q3 | S3 | 訂單編號:(a)ORD- + 8 碼英數(先採用)(b)ORD- + 日期 + 流水號共 16 碼 | S4 | 待決 |
```

## bad example
- 邊界:同一題,因為「格式是 API 的事」就**沒有標擋住**;S4 照 8 碼建了 `varchar(12)` 的主鍵,使用者選了 16 碼之後資料庫要重做
```
| Q3 | S3 | 訂單編號:(a)ORD- + 8 碼英數(先採用)(b)ORD- + 日期 + 流水號共 16 碼 | — | 待決 |
```

# Rule 2 [must] - 和 spec.md 矛盾的做法不算先採用
- 登記每一題之前,把先採用的做法對照 spec.md 的使用者故事、驗收情境、FR、NFR 與 SC;照它做會讓其中一句不成立,就是矛盾
- 矛盾的題目在「問題與可選的做法」引用那一句的原文,拿掉「先採用」,「決定」欄寫「待決」,問使用者時排在最前面;使用者可以改做法,也可以回 specify 改那一句
- 為什麼:planner 的預設做法只管得到它的介面;先採用的做法違反 spec 又混在幾十題建議裡,會被當成一般的建議照單收下,要到 analyze 才被發現,那時合約與任務都要重做

## good example
- 先採用的做法會讓故事 2 那句不成立;**引用原文、拿掉先採用,交給使用者決定**
```
spec.md 故事 2:不論哪一種順序,畫面文字也不會消失或變成兩段

| Q25 | S2 | 和故事 2「不論哪一種順序,畫面文字也不會消失」矛盾:完成前打開編輯器、完成後才儲存,編輯後版本會少這一段。(a)不處理,並回 specify 改那一句(b)儲存時伺服器自動接回(c)儲存時提示 | — | 待決 |
```

## bad example
- 同一題,**先採用了矛盾的做法**,理由是原始版本還在;它看起來和其他建議一樣,只有讀過故事 2 的人才看得出來
```
spec.md 故事 2:不論哪一種順序,畫面文字也不會消失或變成兩段

| Q25 | S2 | 完成前打開編輯器、完成後才儲存,編輯後版本會少這一段:(a)不處理,原始版本仍有,再擷取可補回(先採用)(b)儲存時伺服器自動接回(c)儲存時提示 | — | 待決 |
```

## good example
- 邊界:spec 沒有寫到開著舊頁面時按鈕的狀態;**沒有哪一句被打破,不算矛盾**,照常先採用
```
spec.md:有未結束的工作時按鈕停用並說明原因

| Q24 | S2 | 工作結束後筆記頁的按鈕:(a)不自動更新,開著舊頁面按下去收到 409(先採用)(b)新增輪詢片段 | — | 待決 |
```

## bad example
- 邊界:同一題,因為「看起來和 spec 有關」就**當成矛盾、拿掉先採用**;每一題都這樣標,真正的矛盾又混回去
```
spec.md:有未結束的工作時按鈕停用並說明原因

| Q24 | S2 | 和「按鈕停用並說明原因」矛盾:(a)不自動更新(b)新增輪詢片段 | — | 待決 |
```
