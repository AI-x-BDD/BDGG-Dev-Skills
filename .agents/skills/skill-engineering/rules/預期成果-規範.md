# Rule 1 [must] - 預期成果先從已有上下文取得
- 建立時取得用途、觸發情境、輸入、產出、邊界與成功案例；優化時另取得不滿意的結果及相關對話或執行紀錄。
- 先讀已有上下文，只詢問會影響判斷的缺口；同一份預期成果已確認且仍有效時，沿用該確認。
- 為什麼：重問已提供的資料增加往返，也會讓後續設計忽略使用者已經作過的決定。

## good example
- 已提供的輸入輸出直接沿用，只問影響設計的缺口。
使用者已說明輸入是逐字稿、輸出是決策與待辦；整理這兩項，只補問尚未明確且會影響處理的適用情境。

## bad example
- 同樣的上下文卻要求使用者從頭回答。
使用者已說明輸入是逐字稿、輸出是決策與待辦；仍問「輸入是什麼、輸出是什麼」，沒有使用已有資訊。

# Rule 2 [must] - 工作範圍依使用者要的成果界定
- 本 skill 處理整體建立與優化；一般文字校正或已明確指定的局部操作，直接交對應 Form 或 Deriver，不必擴大成整體重構。
- 為什麼：局部要求的成果已經清楚，擴大盤點與改寫會增加使用者沒有要求的工作。

## good example
- 邊界：已指定局部操作就保留該範圍。
使用者只要求把指定步驟的報告格式抽成樣板；交 derive-template 處理該步驟。

## bad example
- 邊界：同一要求被擴大成整體重構。
使用者只要求把指定步驟的報告格式抽成樣板；卻重新設計所有 Phase 與其他 Rule File。
