# Rule 1 [must] - 預期與現況寫成看得到的產出
- 預期與現況各寫成當時那個輸入交出了什麼、該交出什麼:有幾個、有哪些、長什麼樣;不寫感受
- 使用者只講了感受時,把它換成看得到的產出寫進報告,對不對由使用者在確認時更正
- 為什麼:根因是拿每一步交出的東西去和預期比對才找得到的;預期只是一句感受,走到任何一步都說不出對得上還是對不上,改完之後也沒有東西可以驗收

## good example
- 使用者只說了感受;**報告把它換成數得出來的產出**
```
使用者:替訂單模組加退款那次,提出來的類別圖太大了,看不懂。

輸入:替訂單模組加上退款
現況:類別圖有 12 個類別,其中 7 個是順著相依一路畫進來的既有類別
預期:類別圖只有 5 個類別:新增的 3 個、修改的 1 個,與它們直接用到的 1 個既有類別
```

## bad example
- 同一句話,但**照抄使用者的感受**;走到任何一步,都說不出那一步交出的東西算不算「看得懂」
```
使用者:替訂單模組加退款那次,提出來的類別圖太大了,看不懂。

輸入:替訂單模組加上退款
現況:類別圖太大
預期:類別圖要讓人看得懂
```

## good example
- 邊界:預期寫到**數得出來、指得出是哪幾個**,拿任何一步交出的東西來都比得出結果
```
使用者:替訂單模組加退款那次,提出來的類別圖太大了,看不懂。

輸入:替訂單模組加上退款
現況:類別圖有 12 個類別,其中 7 個是順著相依一路畫進來的既有類別
預期:類別圖只有 5 個類別:新增的 3 個、修改的 1 個,與它們直接用到的 1 個既有類別
```

## bad example
- 邊界:同一句話,預期寫成「只畫必要的類別」,比「看得懂」具體,但**哪些算必要還是說不出來**;拿某一步交出的 12 個類別來比,判不出它偏離了沒有
```
使用者:替訂單模組加退款那次,提出來的類別圖太大了,看不懂。

輸入:替訂單模組加上退款
現況:類別圖有 12 個類別,其中 7 個是順著相依一路畫進來的既有類別
預期:類別圖只畫必要的類別
```

# Rule 2 [must] - 從最上游的那一支 Skill 演練起
- 當時用到不只一支 Skill 時,先排出誰轉交給誰,從最上游那一支收到的輸入開始演練,一路走到交出結果的那一支
- 為什麼:使用者指出的通常是最後交出結果的那一支;問題若是上游交下來的,只演練下游,會把上游的錯看成下游少了一條規則

## good example
- 當時用了兩支 Skill;**從上游的 `plan-scope` 演練起**,在它交給下游的範圍就看到偏離
```
呼叫鏈:plan-scope → plan-with-class-diagram

plan-scope Phase 1 Step 2                交出的範圍是「訂單模組的所有類別」   偏離
plan-with-class-diagram Phase 1 Step 3   照收到的範圍設計出 12 個類別         症狀

根因的位置:plan-scope Phase 1 Step 2
```

## bad example
- 同一次回報,但**只演練了交出類別圖的那一支**;它照收到的範圍設計並沒有錯,卻被當成根因的位置
```
呼叫鏈:plan-scope → plan-with-class-diagram

plan-with-class-diagram Phase 1 Step 3   設計出 12 個類別   偏離

根因的位置:plan-with-class-diagram Phase 1 Step 3
```

# Rule 3 [must] - 演練時只照文字走
- 每一步只照它的原文與它點名載入的檔,寫出它會交出什麼;文字沒寫的事不替它補上,文字互相矛盾時把每一種照著做的結果都寫出來,不替它選一邊
- 為什麼:演練的人知道使用者要什麼,會不自覺地替 Skill 把沒寫的事做對;這樣走下來每一步都對得上,真正出問題的那一段文字反而看不到

## good example
- Step 3 載入的 Rule File 有一條要求畫出完整的相依鏈;**照文字寫出它會交出 12 個類別**
```
Phase 1 Step 3   Think 依 `rules/類別圖-規範.md` 設計這次開發的類別組織。
  載入的檔:rules/類別圖-規範.md
  照文字會交出:〈畫出完整的相依鏈〉要求把相依的既有類別一路畫出來,交出 12 個類別
```

## bad example
- 同一步,但**用自己的判斷替 Skill 把事情做對**;寫出來的是預期的結果,這一步被判成對得上,根因就找不到了
```
Phase 1 Step 3   Think 依 `rules/類別圖-規範.md` 設計這次開發的類別組織。
  載入的檔:rules/類別圖-規範.md
  照文字會交出:合理的設計只會畫這次要動的類別,交出 5 個類別
```

## good example
- 邊界:這一步的文字沒有提到類別框裡要標什麼;**照實寫「沒有寫」**,標不標都算照著做
```
Phase 1 Step 4   Ask 用 Mermaid 提出設計,問使用者是否可以進入開發。
  載入的檔:沒有
  照文字會交出:一張 Mermaid 類別圖;類別框裡要標什麼沒有寫
```

## bad example
- 邊界:同一步,文字沒寫的事**用「通常會這樣做」補上**;看起來合理,但那是演練的人的習慣,不是 Skill 的文字
```
Phase 1 Step 4   Ask 用 Mermaid 提出設計,問使用者是否可以進入開發。
  載入的檔:沒有
  照文字會交出:一張 Mermaid 類別圖,每個類別通常會標出新增、修改或既有
```

# Rule 4 [must] - 根因指到第一個偏離點
- 根因的位置是第一個偏離的步驟;偏離指的是:照這一步交出的東西往下做,預期的產出已經做不出來
- 第一個偏離之後的偏離都記成症狀,不當成根因的位置
- 為什麼:下游的偏離是上游帶下來的;在症狀的位置補規則,上游下次交出的還是同樣的東西,只是多了一條擋不住它的規則

## good example
- 四步都演練過;**根因指到第一個偏離的 Step 3**,使用者看到問題的 Step 4 記成症狀
```
Phase 1 Step 1   讀了訂單模組的程式碼        對得上
Phase 1 Step 2   列出讀到的類別              對得上
Phase 1 Step 3   設計出 12 個類別            偏離
Phase 1 Step 4   提出 12 個類別的類別圖      症狀

根因的位置:Phase 1 Step 3
```

## bad example
- 同一次演練,但**根因指到使用者看到問題的那一步**;在 Step 4 補一條檢查,Step 3 下次設計出來的還是 12 個
```
Phase 1 Step 1   讀了訂單模組的程式碼        對得上
Phase 1 Step 2   列出讀到的類別              對得上
Phase 1 Step 3   設計出 12 個類別            對得上
Phase 1 Step 4   提出 12 個類別的類別圖      偏離

根因的位置:Phase 1 Step 4
```

## good example
- 邊界:Step 1 讀的檔比這次需要的多;但**照它交出的東西往下做,5 個類別的圖仍然做得出來,所以對得上**
```
Phase 1 Step 1   讀了整個訂單模組,包含這次不會動到的檔   對得上
Phase 1 Step 3   設計出 12 個類別                         偏離

根因的位置:Phase 1 Step 3
```

## bad example
- 邊界:同一次演練,因為 Step 1 讀得太多、看起來不理想就**判成偏離**;把讀檔的範圍改小,Step 3 照它載入的規範還是會設計出 12 個
```
Phase 1 Step 1   讀了整個訂單模組,包含這次不會動到的檔   偏離
Phase 1 Step 3   設計出 12 個類別                         症狀

根因的位置:Phase 1 Step 1
```

# Rule 5 [must] - 根因依偏離點的文字由上往下歸類
- 在〈根因指到第一個偏離點〉找到的位置,看管這件事的文字(步驟原文、Rule、樣板或腳本),依下表由上往下歸類,先符合的先用

| 類別 | 偏離點的文字 | 修法 |
|---|---|---|
| 多 | 有文字照著做就會得到現況;拿掉它,剩下的文字會交出預期的產出 | 刪 |
| 錯 | 有文字照著做就會得到現況;拿掉它之後,這件事仍然需要文字來管 | 換 |
| 錯位 | 有文字照著做會得到預期,但走到偏離點時沒有載入它,或它所在的部位管不住這件事 | 搬 |
| 缺 | 當時用到的每一支 Skill 的每一個檔都找過,沒有文字在管這件事 | 加 |

- 部位管不住,指的是固定的格式寫成了 Rule,或結果只由輸入決定的事沒有交給腳本
- 四類都不符時(照著做會得到預期的文字在偏離點有載入,也沒有文字照著做會得到現況),寫明這次的落差不是 Skill 的文字造成的,不歸類,由使用者決定要不要繼續
- 為什麼:四類的修法不一樣,而「加」排在最後;不照順序歸類,每個根因看起來都像少了一條規則,文字只會越加越多,寫錯、多出來、放錯地方的那一段卻原封不動留著

## good example
- 偏離點載入的兩條 Rule 互相衝突;**拿掉照著做會得到現況的那一條,剩下的就會交出預期,歸為「多」**
```
偏離點:Phase 1 Step 3,載入 rules/類別圖-規範.md
  〈只畫這次開發涉及的類別〉   只放新增、修改的類別與它們直接用到的既有類別   ← 照著做會得到預期
  〈畫出完整的相依鏈〉         每個類別相依的既有類別都要一路畫出來           ← 照著做會得到現況

拿掉〈畫出完整的相依鏈〉:剩下的〈只畫這次開發涉及的類別〉會交出 5 個類別
類別:多   修法:刪〈畫出完整的相依鏈〉
```

## bad example
- 同一個偏離點,但**沒有照表往下對,直接當成少了一條規則**;兩條衝突的 Rule 都還在,又多了第三條來排解它們
```
偏離點:Phase 1 Step 3,載入 rules/類別圖-規範.md
  〈只畫這次開發涉及的類別〉   只放新增、修改的類別與它們直接用到的既有類別   ← 照著做會得到預期
  〈畫出完整的相依鏈〉         每個類別相依的既有類別都要一路畫出來           ← 照著做會得到現況

類別:缺   修法:加一條〈兩條 Rule 衝突時以涉及的類別為準〉
```

## good example
- 邊界:這次也找到一條照著做會得到現況的 Rule,但**拿掉它之後沒有文字在管箭頭怎麼選,所以是「錯」不是「多」**
```
現況:所有關係都畫成 -->
預期:繼承畫成 --|>,相依畫成 ..>

偏離點:Phase 1 Step 3,載入 rules/類別圖-規範.md
  〈關係一律畫成實線箭頭〉   ← 照著做會得到現況

拿掉〈關係一律畫成實線箭頭〉:沒有文字說哪一種關係用哪一種箭頭,預期的產出交不出來
類別:錯   修法:把〈關係一律畫成實線箭頭〉換成依關係種類選箭頭的 Rule
```

## bad example
- 邊界:同一個偏離點,因為找到了寫錯的那一條就**歸為「多」,只刪不換**;刪掉之後箭頭怎麼選沒有人管,下次畫出來的可能還是同一種
```
現況:所有關係都畫成 -->
預期:繼承畫成 --|>,相依畫成 ..>

偏離點:Phase 1 Step 3,載入 rules/類別圖-規範.md
  〈關係一律畫成實線箭頭〉   ← 照著做會得到現況

類別:多   修法:刪〈關係一律畫成實線箭頭〉
```

## good example
- 邊界:偏離點載入的 Rule File 裡沒有文字在管類別數量;**把整個資料夾找過一遍,在另一個 Rule File 找到了,歸為「錯位」**
```
現況:類別圖有 12 個類別
預期:類別圖不超過七個類別

偏離點:Phase 1 Step 3,載入 rules/類別圖-規範.md   ← 沒有任何一條在管類別數量
找過:SKILL.md、rules/類別圖-規範.md、rules/實作-規範.md
  rules/實作-規範.md〈類別圖不超過七個類別〉   ← 照著做會得到預期,但 Phase 2 Step 1 才載入

類別:錯位   修法:把〈類別圖不超過七個類別〉搬到 rules/類別圖-規範.md
```

## bad example
- 邊界:同一個偏離點,只看了那一步載入的檔就**歸為「缺」**;加完之後,同一件事在兩個 Rule File 各有一條,下次改數字的人只會改到其中一條
```
現況:類別圖有 12 個類別
預期:類別圖不超過七個類別

偏離點:Phase 1 Step 3,載入 rules/類別圖-規範.md   ← 沒有任何一條在管類別數量

類別:缺   修法:在 rules/類別圖-規範.md 加一條〈類別圖不超過七個類別〉
```

## good example
- 邊界:照著做會得到預期的 Rule 在偏離點有載入,也沒有文字照著做會得到現況;**四類都不符,寫明不是文字造成的,不硬歸一類**
```
現況:類別圖有 9 個類別
預期:類別圖不超過七個類別

偏離點:Phase 1 Step 3,載入 rules/類別圖-規範.md
  〈類別圖不超過七個類別〉   ← 照著做會得到預期,這一步有載入
  沒有任何文字照著做會畫出超過七個

類別:不歸類。這次的落差不是 Skill 的文字造成的,要不要繼續由使用者決定。
```

## bad example
- 邊界:同一個偏離點,為了有東西可以改就**歸為「缺」,再加一條用來強調的 Rule**;同一件事變成兩條在管,原本那一條並沒有寫錯
```
現況:類別圖有 9 個類別
預期:類別圖不超過七個類別

偏離點:Phase 1 Step 3,載入 rules/類別圖-規範.md
  〈類別圖不超過七個類別〉   ← 照著做會得到預期,這一步有載入
  沒有任何文字照著做會畫出超過七個

類別:缺   修法:加一條〈類別數量一定要遵守上限〉
```
