# Rule 1 [must] - 對不上選項的回答先追問
- 回答對不上任何選項、同時選了單選題的兩個選項,或附上的補充和所選的選項矛盾時,不把它整理成決策,只就那一題再問一次
- 為什麼:照字面把矛盾的回答整理成決策,呼叫者拿到的是互相打架的兩句話,只能自己挑一句,AI 又回到替使用者補完需求

## good example
- 「B 但不要登入」和 B 的說明「每個人用自己的手機登入」矛盾;**只就 Q1 追問,累計題數不變**
```
本輪:Q1 誰看得到同一份清單?(B:全家共用同一份清單,每個人用自己的手機登入)
回答:Q1:B 但不要登入

追問 Q1:不登入的話,每支手機要怎麼認得是同一個家?
  A 全家共用一組邀請碼,輸入後就看得到同一份清單,不必登入
  B 還是要登入,只是只登入一次、之後不再問
  Others 以上都不是,請補充
累計題數:1
```

## bad example
- 同一個回答,但**照字面整理成決策**;交還的決策裡同時有「登入」和「不要登入」
```
本輪:Q1 誰看得到同一份清單?(B:全家共用同一份清單,每個人用自己的手機登入)
回答:Q1:B 但不要登入

已確認的決策:全家共用同一份清單,每個人用自己的手機登入
使用者的補充:不要登入
累計題數:1
```

## good example
- 邊界:補充「最近 30 天」看起來不在選項裡,但**它只是把選了的 B 講得更細,沒有和 B 矛盾**,直接整理成決策
```
本輪:Q3 勾掉的品項是直接消失,還是留著當作買過的紀錄?(B:留著當作買過的紀錄)
回答:Q3:B,只留最近 30 天

已確認的決策:勾掉的品項留作買過的紀錄,超過 30 天自動清除
```

## bad example
- 邊界:同一個回答,因為補充不在選項裡就**再追問一次**;使用者已經講清楚了,卻得再答一題
```
本輪:Q3 勾掉的品項是直接消失,還是留著當作買過的紀錄?(B:留著當作買過的紀錄)
回答:Q3:B,只留最近 30 天

追問 Q3:你選的是 B 還是另一種保留方式?
```

# Rule 2 [must] - 追問不計入題數上限
- 依〈對不上選項的回答先追問〉再問的那一題,不計入整場 5 題的上限
- 為什麼:追問若也算一題,使用者答得越認真、補充越多,能問的題目反而越少,真正決定結果的缺口被擠掉

## good example
- Q1 追問了一次,**累計仍是 3 題**,還能再出兩題
```
本輪:Q1、Q2、Q3
Q1 回答矛盾,追問 Q1 一次
累計題數:3,下一輪可以再出 2 題
```

## bad example
- 同一場,但**把追問算成第 4 題**;下一輪只剩 1 題,決定離線設計的那一題被擠掉
```
本輪:Q1、Q2、Q3
Q1 回答矛盾,追問 Q1 一次
累計題數:4,下一輪只能再出 1 題
```

# Rule 3 [must] - 使用者表示要停就不再出題
- 使用者表示不想再回答(例如「先這樣」「不用再問了」「直接做」),就不再出下一輪,即使還有缺口、題數也還沒用完
- 為什麼:使用者喊停之後還繼續出題,他只會隨便選來打發,問出來的答案比沒問還糟

## good example
- 使用者回完就說「先這樣」;**不出下一輪,還沒問的離線缺口寫進剩餘的風險**
```
回答:Q1:B Q2:A,先這樣

剩餘的風險
- 沒有問離線時能不能新增與勾選;如果要支援,資料存放與同步的設計會改變
```

## bad example
- 同一個回答,但**因為題數還沒用完就出了下一輪**
```
回答:Q1:B Q2:A,先這樣

### Q3(單選)沒有網路時還要能新增與勾選嗎
```

## good example
- 邊界:「你決定就好」只針對某一題,**不是要停整場**;那一題採用推薦,其餘缺口照常出下一輪
```
回答:Q1:B Q2:你決定就好

Q2 採用推薦的 A,寫進已確認的決策並註明「使用者交由推薦決定」;下一輪照常出 Q3
```

## bad example
- 邊界:同一個回答,把「你決定就好」**當成要停整場**;還有會改變結果的缺口沒問,就交還了澄清結果
```
回答:Q1:B Q2:你決定就好

不再出題,交還澄清結果
```
