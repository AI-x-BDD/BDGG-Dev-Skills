# Rule 1 [must] - Context 寫到使用者不用回頭查就能選
- 每題的 Context 講清楚三件事:這個缺口是什麼、為什麼現在要決定、選不同的選項會讓結果差在哪裡
- 用到術語時,寫出它對使用者看得到的結果有什麼影響,不只寫術語本身
- 為什麼:使用者是因為需求沒想清楚才被問的,Context 只有一句標題,他得自己回頭查背景、猜每個選項的後果,最後只會回「你決定」,AI 又回到自己補完需求

## good example
- Context **講出缺口、為什麼現在要決定,以及選了會差在哪**,使用者讀完就能選
```
**Context**
需求只說「家人共用」,沒有說共用到什麼程度。這決定要不要做帳號登入:
全家用同一支手機看就不需要帳號;每個人用自己的手機看同一份清單,就要有帳號與邀請家人的流程,工作量大約多一倍。
後面的畫面與資料設計都要先知道這一點。
```

## bad example
- 同一題,但 **Context 只有一句標題**;使用者不知道選哪一個會多出帳號登入
```
**Context**
關於清單的共用範圍。
```

## good example
- 邊界:這題一定要提到同步方式,**術語後面接著寫出使用者看得到的差別**
```
**Context**
家人同時在改同一份清單時,畫面要多快看到別人的變動。即時同步:媽媽一勾掉,爸爸的手機馬上消失;
開啟時同步:要重新打開 App 才看得到,但做起來簡單很多,也比較省電。
```

## bad example
- 邊界:同一題,三件事看起來都有寫,但**只丟出術語**;不懂 WebSocket 的使用者看不出兩個選項對他有什麼差別
```
**Context**
同步機制要用 WebSocket 推播還是開啟時 polling,前者即時、後者實作成本低。
```

# Rule 2 [must] - 選項 2 到 4 個,單選題的選項互斥
- 每題列出 2 到 4 個選項,不含固定的 Others
- 單選題的選項兩兩互斥,選了一個就不會同時符合另一個;每個選項本身都能單獨成立的,寫成多選題
- 為什麼:選項重疊,使用者選了一個,AI 不知道他是不是也要另一個,還是得自己補完;選項太多,使用者得逐一比較,常常挑第一個打發

## good example
- 三個選項**分別是一個人、一份共用、各自一份**,選了一個就不會同時是另一個
```
| 編號 | 選項 | 說明 |
|---|---|---|
| A | 只有自己用 | 不需要帳號 |
| B | 全家共用同一份清單 | 每個人用自己的手機登入,看到的是同一份 |
| C | 每個人各一份,可以分享給家人 | 預設自己看,要分享才邀請 |
| Others | 以上都不是,請補充 | |
```

## bad example
- 同一題,但 **B 包含在 A 裡面**;使用者選 A,看不出他要不要邀請
```
| 編號 | 選項 | 說明 |
|---|---|---|
| A | 家人共用 | 全家一起用 |
| B | 可以邀請家人 | 把家人加進來 |
| C | 每個人各一份,可以分享給家人 | 預設自己看,要分享才邀請 |
| Others | 以上都不是,請補充 | |
```

## good example
- 邊界:要支援的平台**每一個都能單獨成立**,寫成多選題,選項不必互斥
```
### Q3(多選)要在哪些裝置上用?

| 編號 | 選項 | 說明 |
|---|---|---|
| A | iPhone | |
| B | Android 手機 | |
| C | 電腦瀏覽器 | |
| Others | 以上都不是,請補充 | |
```

## bad example
- 邊界:同樣三個選項,但**標成單選題**;全家有人用 iPhone、有人用 Android,使用者被迫只能選一個
```
### Q3(單選)要在哪些裝置上用?

| 編號 | 選項 | 說明 |
|---|---|---|
| A | iPhone | |
| B | Android 手機 | |
| C | 電腦瀏覽器 | |
| Others | 以上都不是,請補充 | |
```

# Rule 3 [must] - 推薦附上取捨原因
- 每題標出推薦:單選題推薦一個選項,多選題推薦一組選項,編號用頓號隔開
- 推薦原因寫出它得到什麼、放棄什麼
- 為什麼:沒有推薦,使用者不知道哪一個是考慮過的預設;只寫「這個最好」,他判斷不了這個取捨合不合他的情況,也就無從推翻 AI 的推薦

## good example
- 推薦原因**寫出得到的與放棄的**
```
**推薦 B**:需求原文就是「家人共用」,B 讓每個人在自己的手機上看到同一份;代價是要做帳號登入與邀請流程。
```

## bad example
- 同一題,但**推薦原因只有一句評價**;使用者不知道選 B 會多出帳號登入
```
**推薦 B**:最適合這個需求。
```

## good example
- 邊界:推薦原因很短,但**放棄的那一半有寫出來**
```
**推薦 B**:符合「家人共用」;代價是要做帳號登入。
```

## bad example
- 邊界:同樣很短,看起來也有寫原因,但**只是把選項換句話再講一次**,得到什麼、放棄什麼都沒有
```
**推薦 B**:因為可以讓全家共用同一份清單。
```

## good example
- 邊界:多選題「要在哪些裝置上用」,**推薦的是一組選項**,原因也寫出這一組得到與放棄的
```
**推薦 A、B**:家裡有人用 iPhone、有人用 Android,兩種手機都支援全家才都能用;代價是要多測一種手機,電腦瀏覽器先不做。
```

## bad example
- 邊界:同一題多選題,為了只標一個而**只推薦 A**;等於建議只支援 iPhone,用 Android 的家人被排除在外
```
**推薦 A**:用 iPhone 的家人最多;代價是用 Android 的家人要等下一版。
```
