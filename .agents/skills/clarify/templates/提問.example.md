### Q1(單選)誰看得到同一份清單

**Context**
需求只說「家人共用」,沒有說共用到什麼程度。這決定要不要做帳號登入:
全家用同一支手機看就不需要帳號;每個人用自己的手機看同一份清單,就要有帳號與邀請家人的流程,工作量大約多一倍。
後面的畫面與資料設計都要先知道這一點。

**總結之提問**:這份購物清單要讓誰看得到、改得到?

| 編號 | 選項 | 說明 |
|---|---|---|
| A | 只有自己用 | 不需要帳號,資料只存在這支手機 |
| B | 全家共用同一份清單 | 每個人用自己的手機登入,看到的是同一份 |
| C | 每個人各一份,可以分享給家人 | 預設自己看,要分享才邀請 |
| Others | 以上都不是,請補充 | |

**推薦 B**:需求原文就是「家人共用」,B 讓每個人在自己的手機上看到同一份;代價是要做帳號登入與邀請流程。

### Q2(單選)家人同時在改時,多快看到別人的變動

**Context**
家人同時在改同一份清單時,畫面要多快看到別人的變動。即時同步:媽媽一勾掉,爸爸的手機馬上消失;
開啟時同步:要重新打開 App 才看得到,但做起來簡單很多,也比較省電。在超市分頭買東西時,這個差別最明顯。

**總結之提問**:別人勾掉或新增品項時,你的手機要馬上更新,還是重新打開才更新?

| 編號 | 選項 | 說明 |
|---|---|---|
| A | 馬上更新 | 分頭買不會重複買,但實作較複雜、較耗電 |
| B | 重新打開 App 才更新 | 實作簡單,分頭買時可能重複買同一樣 |
| Others | 以上都不是,請補充 | |

**推薦 A**:共用清單最常用在超市分頭買,A 能避免重複買;代價是要多做即時同步,也比較耗電。

### Q3(多選)要在哪些裝置上用

**Context**
家裡每個人用的手機不一定一樣。每多支援一種裝置,就要多做一份畫面調整與測試;
沒支援到的裝置,那位家人就打不開這份清單。這也會影響 Q1 的帳號要怎麼登入。

**總結之提問**:家人會用哪些裝置打開這份清單?

| 編號 | 選項 | 說明 |
|---|---|---|
| A | iPhone | 家裡用 iPhone 的人能用 |
| B | Android 手機 | 家裡用 Android 的人能用 |
| C | 電腦瀏覽器 | 在家用電腦也能整理清單 |
| Others | 以上都不是,請補充 | |

**推薦 A、B**:家裡有人用 iPhone、有人用 Android,兩種手機都支援全家才都能用;代價是要多測一種手機,電腦瀏覽器先不做。
