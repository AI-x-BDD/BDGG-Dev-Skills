# Rule 1 [must] - 被相依的類別先實作
- 開始實作一個類別時,它在類別圖上相依的類別都已經實作完;現有的類別視為已經實作完
- 類別圖上每條關係都是左邊相依右邊,所以右邊的先做
- 彼此沒有相依的類別,順序可以隨意
- 為什麼:先做相依別人的那個,就得先寫假的替身或留著編不過,做完一個類別也沒辦法單獨驗

## good example
- **每個類別開始做的時候,它右邊的類別都已經做完**
```
類別圖的關係:
    OrderService --> InventoryChecker
    InventoryChecker --> StockReader
    SqlStockReader ..|> StockReader

開發順序:
    1. StockReader
    2. InventoryChecker
    3. SqlStockReader
    4. OrderService
```

## bad example
- 同一張類別圖,但**從需求的入口開始做**;寫 `OrderService` 的時候 `InventoryChecker` 還不存在
```
類別圖的關係:
    OrderService --> InventoryChecker
    InventoryChecker --> StockReader
    SqlStockReader ..|> StockReader

開發順序:
    1. OrderService
    2. InventoryChecker
    3. StockReader
    4. SqlStockReader
```

## good example
- 邊界:`SqlStockReader` 和 `InventoryChecker` 彼此沒有相依,誰先都可以;但**兩個都相依 `StockReader`,所以 interface 排在它們前面**
```
類別圖的關係:
    InventoryChecker --> StockReader
    SqlStockReader ..|> StockReader

開發順序:
    1. StockReader
    2. SqlStockReader
    3. InventoryChecker
```

## bad example
- 邊界:同一張類別圖,想著「先有實作才有東西可以跑」而先做 `SqlStockReader`;但**實作的箭頭也是左邊相依右邊**,這時候它要實作的 interface 還沒定
```
類別圖的關係:
    InventoryChecker --> StockReader
    SqlStockReader ..|> StockReader

開發順序:
    1. SqlStockReader
    2. StockReader
    3. InventoryChecker
```
