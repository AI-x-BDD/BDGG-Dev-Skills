# Rule 1 [must] - 選型的研究項寫出要對照的同類產品
- 研究項是在幾個方案之間挑一個(前端做法、後端框架、資料怎麼存、怎麼部署)時,列出 1 到 3 個解決同一件事的現有產品,開源或可以自架的優先,並寫出要對照它們的哪一點
- 只查一個技術事實、不用在方案之間挑的研究項(某個 API 的限制、某個工具的參數),不用列
- 為什麼:只比技術本身,容易選出同類產品沒有人這樣做的組合;等使用者問「別人怎麼做」才回頭補查,已經寫好的方案要整段重來

## good example
- 「前端做法」要在幾個方案之間挑,**列出兩個做同一件事的自架產品與要對照的點**
```
R8. 前端:伺服器端渲染、Markdown 與 Mermaid、XSS 防護(FR-003、FR-011、使用者指定)
  同類產品:Pinchflat、YouTubeTLDR —— 對照它們用 SPA 框架還是伺服器端渲染
```

## bad example
- 同一個研究項,但**只列了要比的技術**;research.md 寫完才發現同類產品都沒用 SPA,方案得重新比
```
R8. 前端:伺服器端渲染、Markdown 與 Mermaid、XSS 防護(FR-003、FR-011、使用者指定)
  候選:React SPA、Vue SPA、伺服器端渲染 + htmx
```

## good example
- 邊界:「取得 YouTube 字幕」只查 yt-dlp 能不能取到字幕、要哪些參數,**不用在方案之間挑,不列同類產品**
```
R1. 取得 YouTube 字幕(FR-002、NFR-001、SC-001)
```

## bad example
- 邊界:同一個研究項,**也硬列了同類產品**;要查的是一個工具的行為,別的產品怎麼做不會改變答案,只多了一次查證
```
R1. 取得 YouTube 字幕(FR-002、NFR-001、SC-001)
  同類產品:Pinchflat、Whishper —— 對照它們怎麼取字幕
```
