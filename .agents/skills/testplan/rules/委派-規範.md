# Rule 1 [must] - 每個端點節寫成自己的檔,主 agent 不重打
- 主 agent 寫骨架、跨端點驗收與全域測試區,並驗收每一節;subagent 用哪個模型照使用者為這個階段的選擇,這份規範不另外指定
- 每個 subagent 把它那一節的內容寫成 `<spec package>/.testplan-parts/US<故事序號>-<端點代號>.md`:只寫節標題底下的內容(案例表與說明),不寫節標題,節標題由主 agent 的骨架提供;補案例時只寫要補的那幾列;回報裡只寫檔案路徑、案例數、涵蓋的需求、操作 × 錯誤碼與待決問題,不把整節案例貼在回報裡
- 主 agent 不重打端點節的內容,由 `assemble_testplan.py` 接進 testplan.md;拼完、檢查都過之後刪掉 `.testplan-parts/`
- 為什麼:主 agent 重打 subagent 已經寫好的內容,是同一份東西生成兩次,還可能抄漏;colab-gpu-bridge 002 的主 agent 把 4 個端點節交回的原文又打了一遍(35k 字元),testplan 階段 20 分鐘裡主 agent 自己就占了 18.7 分

## good example
- 4 個端點節平行;**各自寫成檔,主 agent 只在骨架留位置,用腳本接進來**
```
Agent × 4 → .testplan-parts/US1-LIB.md、US1-API.md、US2-LIB.md、US2-API.md
骨架:### 2.1 E8 Ollama 官方模型庫
      <!-- 端點節:US1-LIB.md -->
uv run scripts/assemble_testplan.py --skeleton …/testplan.skeleton.md --parts …/.testplan-parts --out …/testplan.md
```

## bad example
- 同 4 節,subagent 把整節案例貼在回報裡,**主 agent 再逐字寫進 testplan.md**;多花一倍的生成時間,抄的時候還可能漏一列
```
Write testplan.md(主 agent 把 4 份回報的案例表重打一遍)
```

## good example
- 邊界:這次只補一個端點節的兩個案例;**照樣寫成檔、用腳本接**,骨架就是現有的 testplan.md,在那一節的尾巴留位置
```
骨架:現有的 testplan.md,在 4.4 E8 節尾加一行 <!-- 端點節:US2-LIB-補.md -->
```

## bad example
- 邊界:同一次補案例,因為「只有兩個案例」就**請 subagent 直接改 testplan.md**;subagent 順手改了別節的編號,主 agent 對不出改了哪裡
```
subagent:直接編輯 specs/002-library-error-handling/testplan.md
```
