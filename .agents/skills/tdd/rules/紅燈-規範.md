# Rule 1 [must] - 測試的紅燈要是斷言失敗
- 測試任務寫完要跑一次,看到的失敗必須是斷言失敗:測試載入了、呼叫了被測的函式、拿到的值和預期不同
- 被測的模組還不存在時,先建立只有簽名、回傳錯誤值的空殼,讓測試載入得了;空殼不算實作任務做完
- 為什麼:`import` 失敗、檔案不存在、語法錯誤也是紅燈,但那種紅燈在實作寫出來之前就決定了結果,測試裡的斷言一條都沒跑過,寫錯了也不會有人發現

## good example
- T010 寫完時 `digits.ts` 還不存在;**先建空殼,跑出來是斷言失敗**
```
T010 撰寫 shared/test/digits.test.ts
  空殼:shared/src/digits.ts 匯出 validateDigits(s) { return "DIGITS_FORMAT_INVALID" }
  紅燈:7 個案例中 2 個失敗
    AssertionError: validateDigits("1234") 預期 null,實際 "DIGITS_FORMAT_INVALID"
```

## bad example
- 同一個測試,**沒有空殼就跑**;失敗訊息是找不到模組,7 個斷言一個都沒有執行
```
T010 撰寫 shared/test/digits.test.ts
  紅燈:Error [ERR_MODULE_NOT_FOUND]: Cannot find module 'shared/src/digits.ts'
```

## good example
- 邊界:空殼讓 7 個案例中 5 個意外通過(剛好都該回 `DIGITS_FORMAT_INVALID`);**仍然有斷言失敗,而且失敗的是該失敗的那 2 個**,這是對的紅燈
```
紅燈:7 個案例中 2 個失敗("1234"、"0123" 預期 null)
```

## bad example
- 邊界:空殼寫成直接呼叫 `throw new Error("TODO")`;每個案例都失敗,看起來很紅,但**失敗的原因是例外,不是回傳值和預期不同**,斷言其實沒有比對過任何值
```
紅燈:7 個案例全部失敗
  Error: TODO
```

# Rule 2 [must] - 案例已被滿足時,用對照組取得斷言失敗
- 測試寫完一執行就通過,表示現有的程式已經做到這個案例;這時不重寫測試,也不刪掉它
- 暫時放入案例「要抓的錯」那種錯誤實作,執行確認這個測試因此斷言失敗;再撤回,執行一次確認回到綠燈
- 放入錯誤實作優先用 monkeypatch 或 fixture,只在這次的測試行程裡生效;非改原始檔不可時,改完立刻撤回,撤回後清掉 `__pycache__`,用 `git diff` 確認原始檔回到原樣
- 紅燈證據寫明「對照組」、放入的是哪一種錯誤實作,以及斷言失敗的訊息
- 為什麼:測試寫完就綠,說不出它抓不抓得到要抓的錯;對照組用一個真的錯誤實作證明它抓得到。直接改共用的原始檔,在平行開發時會被別人的測試跑到、被一起提交,撤回後還可能跑到舊的快取:colab-gpu-bridge 002 的 E2 subagent 斷在改壞的半途,三行錯誤實作就留在共用檔裡

## good example
- US2-LIB-09 寫完就通過(故事 1 的 `_get` 已經接住傳輸層例外);**用 monkeypatch 讓 `_get` 不接 `ConnectError`,斷言失敗後撤回**,原始檔沒有改
```
紅燈(對照組):寫完執行 1 passed
  monkeypatch.setattr(model_library, "_get", _get_without_transport_catch)
  → AssertionError: expected AdapterError(LIBRARY_UNREACHABLE), got httpx.ConnectError
  撤回後執行 1 passed;git diff src/ 沒有輸出
```

## bad example
- 同一個案例,**為了拿到紅燈,把測試的斷言改成一定失敗**,再改回來;證明的是斷言會失敗,不是測試抓得到 `ConnectError` 原樣往上拋
```
紅燈:assert result.code == "LIBRARY_UNREACHABLE"  改成  == "X"  → 1 failed
綠燈:改回來 → 1 passed
```

## good example
- 邊界:錯誤實作只能放在模組層級的常數,monkeypatch 改不到呼叫端已經讀進去的值;**改原始檔、立刻撤回,清快取並用 `git diff` 確認**
```
紅燈(對照組):把 errors.py 的 LIBRARY_STATUS 裡 LIBRARY_CLOUD_ONLY 暫時移除 → 1 failed(expected 422, got 502)
撤回;rm -rf src/cgb/**/__pycache__;git diff src/cgb/domain/errors.py 沒有輸出;執行 1 passed
```

## bad example
- 邊界:同一個情況,改了原始檔做完對照組,**沒有用 `git diff` 確認就交回**;撤回少了一行,`LIBRARY_CLOUD_ONLY` 被留在註解裡,下一個任務的測試開始跑出 502
```
紅燈(對照組):暫時移除 LIBRARY_CLOUD_ONLY → 1 failed
撤回(手動把那一行貼回去)→ 交回
```
