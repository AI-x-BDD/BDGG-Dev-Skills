# Rule 1 [must] - 腳本執行規範照固定內容寫
- 檔案放在目標 skill 的 `rules/腳本執行-規範.md`,內容固定如下,照抄不改寫

````markdown
# Rule 1 [must] - 腳本路徑從本 skill 的目錄算起
- 步驟裡的 `scripts/<檔名>.py` 相對於本 skill 的目錄(SKILL.md 所在的那一層),執行時換成實際路徑
- 為什麼:執行時的工作目錄是使用者的專案,不是 skill 的目錄;照抄相對路徑會找不到檔

## good example
- 工作目錄是使用者的專案,**腳本路徑換成了本 skill 目錄底下的實際路徑**
```
本 skill    .claude/skills/rule-audit/
步驟的指令  uv run scripts/count_rules.py --skill <目標 skill 路徑>

$ uv run .claude/skills/rule-audit/scripts/count_rules.py --skill .claude/skills/order-flow
```

## bad example
- 同一步,但**照抄步驟裡的相對路徑**;使用者的專案底下沒有 `scripts/count_rules.py`,這一步直接失敗
```
本 skill    .claude/skills/rule-audit/
步驟的指令  uv run scripts/count_rules.py --skill <目標 skill 路徑>

$ uv run scripts/count_rules.py --skill .claude/skills/order-flow
```

## good example
- 邊界:使用者的專案自己也有 `scripts/` 目錄,照抄相對路徑不會找不到檔;**執行的仍然是本 skill 底下的那一支**
```
本 skill    .claude/skills/rule-audit/
使用者專案  scripts/count_rules.py   ← 專案自己的另一支腳本,剛好同名

$ uv run .claude/skills/rule-audit/scripts/count_rules.py --skill .claude/skills/order-flow
```

## bad example
- 邊界:同一個專案,照抄相對路徑,指令順利跑完、看起來沒有問題;但**跑的是專案自己那一支同名的腳本**,拿到的不是這一步要的結果
```
本 skill    .claude/skills/rule-audit/
使用者專案  scripts/count_rules.py   ← 專案自己的另一支腳本,剛好同名

$ uv run scripts/count_rules.py --skill .claude/skills/order-flow
```

# Rule 2 [must] - 照步驟寫的 `uv run` 執行
- 指令照步驟寫的執行;不 `pip install`,也不直接用 `python` 跑
- 為什麼:第三方套件宣告在腳本檔頭,`uv run` 會讀它並裝進隔離的環境;用 `python` 跑會在 import 失敗,`pip install` 會把套件裝進使用者系統的 Python

## good example
- 這支腳本用到 `pyyaml`,**照步驟寫的 `uv run` 執行**,套件由 uv 裝進隔離的環境
```
$ uv run .claude/skills/rule-audit/scripts/check_frontmatter.py --skill .claude/skills/order-flow
```

## bad example
- 同一支腳本,但**改用 `python` 跑**;import 失敗之後又 `pip install`,套件裝進了使用者系統的 Python
```
$ python .claude/skills/rule-audit/scripts/check_frontmatter.py --skill .claude/skills/order-flow
ModuleNotFoundError: No module named 'yaml'
$ pip install pyyaml
```

## good example
- 邊界:這支腳本只用到標準函式庫,用 `python` 也跑得動;**仍然照步驟寫的 `uv run` 執行**
```
$ uv run .claude/skills/rule-audit/scripts/count_rules.py --skill .claude/skills/order-flow
```

## bad example
- 邊界:同一支腳本,因為沒有第三方套件就改用 `python` 跑,今天跑得動;但**檔頭宣告的 Python 版本沒有人看**,腳本日後加了套件,同一行指令就在 import 失敗
```
$ python .claude/skills/rule-audit/scripts/count_rules.py --skill .claude/skills/order-flow
```

# Rule 3 [must] - 找不到 `uv` 先問使用者
- 問使用者是否安裝 uv(https://docs.astral.sh/uv/getting-started/installation/);不安裝就把指令裡的 `uv run` 換成 `pipx run`
- 為什麼:在使用者的機器上裝工具要他同意,沒問就裝,他的機器上會多一個他不知道的工具;`pipx run` 同樣讀得懂檔頭的套件宣告,不裝 uv 也跑得了

## good example
- 找不到 `uv`,**先問使用者**,他同意之後才安裝
```
$ uv run .claude/skills/rule-audit/scripts/check_frontmatter.py --skill .claude/skills/order-flow
bash: uv: command not found

問使用者:這一步要用 uv 執行腳本,但這台機器沒有 uv。要安裝嗎?(https://docs.astral.sh/uv/getting-started/installation/)
使用者:好,裝吧。
```

## bad example
- 同一個情況,但**沒有問就自己裝了**
```
$ uv run .claude/skills/rule-audit/scripts/check_frontmatter.py --skill .claude/skills/order-flow
bash: uv: command not found

$ curl -LsSf https://astral.sh/uv/install.sh | sh
```

## good example
- 邊界:使用者不想安裝;**把指令裡的 `uv run` 換成 `pipx run`**,其餘照原樣
```
使用者:不要裝。

$ pipx run .claude/skills/rule-audit/scripts/check_frontmatter.py --skill .claude/skills/order-flow
```

## bad example
- 邊界:同一個回答,因為使用者說不裝就改用 `python` 跑;看起來是照他的意思做,但**檔頭宣告的 `pyyaml` 沒有人裝**,腳本在 import 失敗
```
使用者:不要裝。

$ python .claude/skills/rule-audit/scripts/check_frontmatter.py --skill .claude/skills/order-flow
```
````

- 一支 skill 只有一個 `rules/腳本執行-規範.md`,不論它有幾支腳本
- 為什麼:腳本是被執行而不是被讀的,這三條 Rule 是執行的人唯一讀得到的執行說明;少了任何一條,他遇到找不到 `uv` 或 import 失敗時,只會照自己的習慣把套件 `pip install` 進系統的 Python

## good example
- 目標 skill 的 `rules/` 底下**就是那三條 Rule,一字未改**
```
rules/
└── 腳本執行-規範.md
    # Rule 1 [must] - 腳本路徑從本 skill 的目錄算起
    # Rule 2 [must] - 照步驟寫的 `uv run` 執行
    # Rule 3 [must] - 找不到 `uv` 先問使用者
```

## bad example
- 同一支 skill,但內容**用自己的話重寫成一條**;路徑相對於哪裡、找不到 `uv` 怎麼辦都不見了
```
rules/
└── 腳本執行-規範.md
    # Rule 1 [must] - 腳本用 `uv run` 執行
```

## good example
- 邊界:這支 skill 後來有了第二支腳本,**檔案仍然是那三條 Rule**;每支腳本怎麼用,寫在步驟的指令與它自己的 `--help` 裡
```
scripts/
├── count_rules.py
└── check_frontmatter.py

rules/
└── 腳本執行-規範.md
    # Rule 1 [must] - 腳本路徑從本 skill 的目錄算起
    # Rule 2 [must] - 照步驟寫的 `uv run` 執行
    # Rule 3 [must] - 找不到 `uv` 先問使用者
```

## bad example
- 邊界:同一支 skill,在三條之後替每支腳本各加一條用法;看起來更完整,但**同樣的用法現在寫在三個地方**,腳本的參數一改,這裡就和步驟、`--help` 對不上
```
scripts/
├── count_rules.py
└── check_frontmatter.py

rules/
└── 腳本執行-規範.md
    # Rule 1 [must] - 腳本路徑從本 skill 的目錄算起
    # Rule 2 [must] - 照步驟寫的 `uv run` 執行
    # Rule 3 [must] - 找不到 `uv` 先問使用者
    # Rule 4 [must] - `count_rules.py` 用 `--skill` 指定目標 skill
    # Rule 5 [must] - `check_frontmatter.py` 用 `--skill` 指定目標 skill
```
