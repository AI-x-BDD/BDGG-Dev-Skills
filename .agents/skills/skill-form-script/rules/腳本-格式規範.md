# Rule 1 [must] - 腳本只用 Python 寫
- `scripts/` 底下每支腳本都是 `.py` 檔,不寫 shell script、PowerShell 或其他語言
- 為什麼:shell script 在沒有 bash 的 Windows 上跑不起來,PowerShell 在 macOS、Linux 上通常沒有裝;Python 加上 `uv run` 才是三個平台都能用同一行指令執行的組合

## good example
- 數 Rule 條數這件事**寫成 `.py`**,三個平台都用同一行指令執行
```
scripts/
└── count_rules.py

uv run scripts/count_rules.py --skill <目標 skill 路徑>
```

## bad example
- 同一件事,但**寫成 shell script**;在沒有 bash 的 Windows 上,這一步直接失敗
```
scripts/
└── count_rules.sh

bash scripts/count_rules.sh <目標 skill 路徑>
```

# Rule 2 [must] - 腳本單檔自足
- 一支腳本的程式碼全部寫在同一個 `.py` 檔,不 import 同目錄或 skill 裡的其他 `.py` 檔
- 兩支腳本用得到同一段程式碼時,各自寫一份
- 為什麼:依賴是宣告在被執行的那個檔的檔頭,共用的模組沒有地方宣告自己要的套件;腳本一旦互相 import,就得當成一個 Python 專案來維護

## good example
- 讀 Rule 標題的函式**就寫在這支腳本裡**,整支腳本只有一個檔
```python
# scripts/count_rules.py
import re
from pathlib import Path

RULE_TITLE = re.compile(r"^# Rule \d+ \[(must|should)\] - ")


def rule_strengths(text: str) -> list[str]:
    ...
```

## bad example
- 同一支腳本,但**把那個函式搬到另一個檔再 import**;`common.py` 之後用到的套件沒有地方宣告,改它的時候也得同時顧到每一支 import 它的腳本
```python
# scripts/count_rules.py
from pathlib import Path

from common import rule_strengths   # scripts/common.py
```

## good example
- 邊界:import 的是**標準函式庫與檔頭宣告的第三方套件**,不是 skill 裡的另一個檔,仍然是單檔
```python
# scripts/check_frontmatter.py
import json
from pathlib import Path

import yaml
```

## bad example
- 邊界:共用的函式放在底線開頭的 `_utils.py`,看起來不算一支腳本,但**它仍然是另一個要一起維護的檔**
```python
# scripts/check_frontmatter.py
import json
from pathlib import Path

import yaml
from _utils import read_frontmatter   # scripts/_utils.py
```

# Rule 3 [must] - 第三方套件宣告在檔頭的 PEP 723 區塊
- 每支腳本的最前面都有 PEP 723 區塊,列出 `requires-python` 與 `dependencies`,格式如下

```python
# /// script
# requires-python = ">=<最低的 Python 版本>"
# dependencies = [
#   "<套件名><版本範圍>",
# ]
# ///
```

- 只用到標準函式庫的腳本也寫這個區塊,`dependencies = []`
- 依賴只寫在這裡,不另外放 `requirements.txt`、`pyproject.toml`,也不建 venv
- 為什麼:執行的人只會照步驟跑 `uv run`,uv 是從這個區塊知道要裝什麼的;依賴寫在別的檔,沒有人會去讀,腳本就在 import 那一行失敗

## good example
- 用到 `pyyaml`,**宣告就在檔頭**;`uv run` 讀到之後自己裝進隔離的環境
```python
# /// script
# requires-python = ">=3.10"
# dependencies = [
#   "pyyaml>=6,<7",
# ]
# ///
"""讀出目標 skill 的 SKILL.md frontmatter。"""
import yaml
```

## bad example
- 同一支腳本,但**依賴寫在旁邊的 `requirements.txt`,檔頭沒有區塊**;`uv run` 不會讀那個檔,執行到 `import yaml` 就失敗
```
scripts/
├── check_frontmatter.py   ← 第一行就是 """讀出目標 skill 的 SKILL.md frontmatter。"""
└── requirements.txt       ← pyyaml>=6,<7
```

## good example
- 邊界:這支腳本只用到標準函式庫,**區塊仍然在,`dependencies` 是空的**
```python
# /// script
# requires-python = ">=3.10"
# dependencies = []
# ///
"""統計目標 skill 每個 Rule File 的 Rule 條數與各條的強度。"""
import argparse
import json
```

## bad example
- 邊界:同一支腳本,因為沒有第三方套件就**整個區塊省略**;在使用者的 Python 專案目錄底下執行時,`uv run` 會把它當成那個專案的一部分,先去裝專案的依賴,並在專案裡留下 `.venv` 與 `uv.lock`
```python
"""統計目標 skill 每個 Rule File 的 Rule 條數與各條的強度。"""
import argparse
import json
```

# Rule 4 [must] - 每個第三方套件寫版本範圍
- `dependencies` 的每一項都寫出下限與上限,上限寫到下一個主版本:`"<套件名>>=<下限>,<<下一個主版本>"`
- 為什麼:沒有上限,uv 在每一台新機器上裝的都是當下最新版;套件出了不相容的主版本,腳本沒有人改過卻壞了

## good example
- **下限與上限都在**,主版本 7 出來之後,裝到的仍然是 6
```python
# dependencies = [
#   "pyyaml>=6,<7",
# ]
```

## bad example
- 同一個套件,但**只寫了名字**;哪一天裝到哪一版,由執行當下的 PyPI 決定
```python
# dependencies = [
#   "pyyaml",
# ]
```

## good example
- 邊界:腳本用到 6.0.1 才有的功能,下限寫到修訂號,**上限仍然在**
```python
# dependencies = [
#   "pyyaml>=6.0.1,<7",
# ]
```

## bad example
- 邊界:同一個套件寫了 `>=6`,看起來已經有版本,但**沒有上限**,主版本 7 出來照樣會被裝進來
```python
# dependencies = [
#   "pyyaml>=6",
# ]
```

# Rule 5 [must] - 輸入只走命令列參數
- 腳本需要的每一項輸入都用 `argparse` 定義成命令列參數;不呼叫 `input()`,也不停下來等任何確認
- 少了必要的參數就直接結束,不改成詢問
- 為什麼:執行的人是 AI,它的 shell 沒有人可以打字;腳本一停下來等輸入,那一步就卡到逾時

## good example
- 目標 skill 的路徑**從 `--skill` 進來**,少了它腳本馬上結束並說缺什麼
```python
parser = argparse.ArgumentParser(description=__doc__)
parser.add_argument("--skill", required=True, type=Path, help="目標 skill 的根目錄(含 SKILL.md 的那一層)")
args = parser.parse_args()
```

## bad example
- 同一項輸入,但**用 `input()` 問**;執行的人沒辦法回答,這一步停在這裡不動
```python
skill = Path(input("目標 skill 的路徑: "))
```

## good example
- 邊界:這支腳本會覆寫檔案,需要使用者同意;同意與否**也是一個旗標**,由執行的人問過使用者之後帶進來
```python
parser.add_argument("--force", action="store_true", help="輸出檔已存在時直接覆寫")
args = parser.parse_args()

if args.output.exists() and not args.force:
    print(f"錯誤: {args.output} 已存在。要覆寫請加上 --force。", file=sys.stderr)
    sys.exit(1)
```

## bad example
- 邊界:同一支腳本,輸入都走參數了,但**覆寫前的確認仍然是 `input()`**;看起來比較安全,實際上這一步永遠等不到回答
```python
args = parser.parse_args()

if args.output.exists() and input(f"{args.output} 已存在,要覆寫嗎? [y/N] ") != "y":
    sys.exit(1)
```

# Rule 6 [must] - `--help` 說明用途與每個參數
- `ArgumentParser` 的 `description` 寫這支腳本做什麼,每個參數都有 `help`
- 為什麼:腳本是被執行而不是被讀的,執行的人要知道參數怎麼下,只會跑 `--help`;說明是空的,他就得把整支腳本讀進來

## good example
- `--help` 的輸出**寫出腳本做什麼、`--skill` 要給什麼**,不必打開腳本
```
usage: count_rules.py [-h] --skill SKILL

統計目標 skill 每個 Rule File 的 Rule 條數與各條的強度。

options:
  -h, --help     show this help message and exit
  --skill SKILL  目標 skill 的根目錄(含 SKILL.md 的那一層)
```

## bad example
- 同一支腳本,但 **`description` 與 `help` 都沒寫**;看得到有 `--skill`,看不出要給檔案、目錄還是 skill 的名字
```
usage: count_rules.py [-h] --skill SKILL

options:
  -h, --help     show this help message and exit
  --skill SKILL
```

## good example
- 邊界:`help` 只有一句,但**說得出要給的是哪一層目錄**,執行的人不會把 SKILL.md 的路徑或 skill 的名字傳進來
```python
parser.add_argument("--skill", required=True, type=Path, help="目標 skill 的根目錄(含 SKILL.md 的那一層)")
```

## bad example
- 邊界:同一個參數,`help` 有寫,`--help` 也印得出來,但**「路徑」沒有說是什麼的路徑**,和沒寫一樣要用猜的
```python
parser.add_argument("--skill", required=True, type=Path, help="路徑")
```

# Rule 7 [must] - 結果寫 stdout、診斷寫 stderr
- 那一步要拿去用的結果寫到 stdout;進度、警告與錯誤訊息寫到 stderr
- 為什麼:執行的人是拿 stdout 當結果往下用的;進度訊息混在裡面,結果就解析不出來

## good example
- 進度**寫到 stderr**,stdout 只有結果
```python
print(f"讀到 {len(result)} 個 Rule File", file=sys.stderr)
json.dump(result, sys.stdout, ensure_ascii=False)
```
```
stdout  {"RuleFile-格式規範.md": {"must": 8, "should": 2}}
stderr  讀到 1 個 Rule File
```

## bad example
- 同一支腳本,但**進度也用 `print()` 印到 stdout**;結果前面多了一行,整份輸出不再是合法的 JSON
```python
print(f"讀到 {len(result)} 個 Rule File")
json.dump(result, sys.stdout, ensure_ascii=False)
```
```
stdout  讀到 1 個 Rule File
        {"RuleFile-格式規範.md": {"must": 8, "should": 2}}
```

## good example
- 邊界:`rules/` 底下一個 Rule File 都沒有;**stdout 仍然是結果(空的),說明寫到 stderr**
```
stdout  {}
stderr  讀到 0 個 Rule File
```

## bad example
- 邊界:同一個情況,把「沒有 Rule File」印到 stdout;看起來是在回報結果,但**那是給人看的說明**,拿 stdout 去解析的人得到的不是結果
```
stdout  rules/ 底下沒有 Rule File
```

# Rule 8 [should] - stdout 的結果用 JSON
- 結果是要被取值的資料時,以一份 JSON 寫到 stdout
- 結果本身就是要原樣交出去的文字(例如一段要貼進文件的 Markdown)時,可以直接輸出那段文字
- 為什麼:用空白對齊的表格,欄位裡一有空白就切不開;JSON 的欄位邊界明確,執行的人與 `jq` 都能直接取值

## good example
- 條數與強度**是一份 JSON**,要哪個檔的哪個數字都取得到
```
{"SOP-格式規範.md": {"must": 8, "should": 1}, "把關紀錄-格式規範.md": {"must": 4, "should": 1}}
```

## bad example
- 同一份結果,但**排成給人看的表格**;執行的人得自己數第幾欄才知道哪個數字是 must
```
檔名                     must  should
SOP-格式規範.md          8     1
把關紀錄-格式規範.md     4     1
```

## good example
- 邊界:這支腳本的產出是一段要原樣貼進報告的 Markdown,**沒有人要從裡面取值**,所以直接輸出
```
| Rule File | must | should |
|---|---|---|
| SOP-格式規範.md | 8 | 1 |
```

## bad example
- 邊界:下一步要拿 must 的條數來判斷,結果卻因為「Markdown 比較好讀」而輸出成表格;**這份結果是要被取值的資料**,不是要原樣交出去的文字
```
| Rule File | must | should |
|---|---|---|
| SOP-格式規範.md | 8 | 1 |
```

# Rule 9 [must] - 失敗時以非零 exit code 結束
- 沒有做完該做的事,就以非零的 exit code 結束;exit code 0 只代表做完了
- 為什麼:執行的人先看 exit code 決定下一步;失敗卻回 0,他會拿著空的或不完整的結果繼續往下做

## good example
- 找不到 `rules/` 就**以 exit code 1 結束**
```python
if not rules_dir.is_dir():
    print(f"錯誤: {args.skill} 底下沒有 rules/ 目錄。", file=sys.stderr)
    sys.exit(1)
```

## bad example
- 同一個情況,但**印完訊息就正常結束**;exit code 是 0,stdout 是空的,執行的人以為這支 skill 沒有任何 Rule
```python
if not rules_dir.is_dir():
    print(f"錯誤: {args.skill} 底下沒有 rules/ 目錄。", file=sys.stderr)
    return
```

## good example
- 邊界:`rules/` 存在,只是裡面沒有 Rule File;**該做的事做完了,結果是空的**,所以 exit code 是 0
```
$ uv run scripts/count_rules.py --skill <沒有 Rule File 的 skill>
{}
$ echo $?
0
```

## bad example
- 邊界:為了讓腳本「不會掛掉」,把所有例外接住並輸出空的結果;看起來很穩,但**讀檔失敗與沒有 Rule File 變成同一種輸出**,exit code 也都是 0
```python
try:
    result = count(rules_dir)
except Exception:
    result = {}
json.dump(result, sys.stdout, ensure_ascii=False)
```

# Rule 10 [must] - 錯誤訊息寫出哪裡錯與怎麼修
- 錯誤訊息寫出收到什麼、預期什麼,讓執行的人知道下一次指令要怎麼改
- 為什麼:執行的人下一次怎麼試,全看這段訊息;只寫「輸入錯誤」,他只能用猜的,或把整支腳本讀進來找原因

## good example
- 訊息寫出**收到的路徑、缺的是什麼、`--skill` 該給哪一層**
```
錯誤: .claude 底下沒有 rules/ 目錄。--skill 要給 skill 的根目錄(含 SKILL.md 的那一層)。
```

## bad example
- 同一個錯誤,但**只說不對**;執行的人不知道是路徑打錯、給錯層,還是這支 skill 本來就沒有 Rule File
```
錯誤: 路徑不正確
```

## good example
- 邊界:少了必要參數時,`argparse` 自己印的訊息**已經寫出缺哪個參數與用法**,不必再包一層
```
usage: count_rules.py [-h] --skill SKILL
count_rules.py: error: the following arguments are required: --skill
```

## bad example
- 邊界:同一個「沒有 rules/」的錯誤,沒有檢查就讓例外噴出來;traceback 很長、路徑也在裡面,但**沒有說預期的是什麼**,執行的人還是不知道 `--skill` 該給哪一層
```
Traceback (most recent call last):
  File "scripts/count_rules.py", line 18, in <module>
    main()
  File "scripts/count_rules.py", line 14, in main
    for path in sorted(rules_dir.iterdir()):
                ^^^^^^^^^^^^^^^^^^^^^^^^^^^
  ...
FileNotFoundError: [Errno 2] No such file or directory: '.claude/rules'
```

# Rule 11 [must] - 讀寫文字檔明確指定 encoding
- 每一次讀寫文字檔(`open()`、`Path.read_text()`、`Path.write_text()`)都寫出 `encoding`;沒有理由用別的,就寫 `utf-8`
- 為什麼:沒有指定時,Python 可能改用作業系統的預設編碼,繁體中文 Windows 是 cp950;同一支腳本在 macOS、Linux 讀得了的中文檔,到了 Windows 就解碼失敗或讀成亂碼

## good example
- 讀 Rule File 時**寫出 `encoding="utf-8"`**,三個平台讀到的內容一樣
```python
text = path.read_text(encoding="utf-8")
```

## bad example
- 同一行,但**沒有指定**;Rule File 裡都是中文,在預設編碼是 cp950 的機器上讀不進來
```python
text = path.read_text()
```

## good example
- 邊界:要讀的是一份已知用 Big5 存的舊 CSV,寫的不是 `utf-8`,但**編碼仍然是明確寫出來的**
```python
rows = path.read_text(encoding="cp950").splitlines()
```

## bad example
- 邊界:寫出的是 `json.dumps()` 的結果,它預設只輸出 ASCII,看起來不指定也沒事;但**哪一天加上 `ensure_ascii=False`,這一行就開始依賴那台機器的預設編碼**
```python
output.write_text(json.dumps(result))
```

# Rule 12 [should] - 路徑用 `pathlib` 組合
- 路徑用 `pathlib.Path` 與 `/` 運算子組合,不用字串相加或 f-string 拼出來
- 為什麼:拼字串時分隔符號是寫的人那台機器的;寫死的 `\` 到了 macOS、Linux 不是一層目錄,而是檔名裡的一個字元

## good example
- `rules/` 的路徑**用 `/` 運算子接出來**,分隔符號由 `pathlib` 依平台決定
```python
rules_dir = args.skill / "rules"
for path in sorted(rules_dir.glob("*.md")):
    ...
```

## bad example
- 同一段,但**用字串相加並寫死反斜線**;在 macOS、Linux 上找的是一個名字裡有 `\rules` 的目錄
```python
rules_dir = str(args.skill) + "\\rules"
for name in sorted(os.listdir(rules_dir)):
    ...
```

## good example
- 邊界:要呼叫的函式只收字串,所以轉成 `str`;**路徑本身仍然是用 `pathlib` 組合的**
```python
rules_dir = args.skill / "rules"
names = sorted(os.listdir(str(rules_dir)))
```

## bad example
- 邊界:同一段用 f-string 與正斜線拼接,三個平台大多跑得動,看起來沒有問題;但 `--skill` 在 Windows 上傳進來的是 `C:\…\skill`,**拼出來的路徑混了兩種分隔符號**,印在結果與錯誤訊息裡就對不回實際的檔
```python
rules_dir = f"{args.skill}/rules"
names = sorted(os.listdir(rules_dir))
```
