# Rule 1 [must] - 任務指示檔以 `-p "$(cat 檔)"` 傳入
- 任務指示先存成檔,調用時用 `-p "$(cat <指示檔路徑>)"` 把全文當成 `-p` 的引數
- 禁止 `-p - < 檔`,也禁止把指示內容直接打在命令列
- 為什麼:agy 1.4.4(2026-10-22 重測)的 `-p` 把後面那個引數當成指示本身,不讀 stdin;`-p - < 檔` 會讓 agy 只收到一個 `-`,exit 0 卻沒有做事。把內容直接打在命令列,引號、換行與 `$` 會先被 shell 改掉

## good example
- 指示檔的全文**由 `"$(cat …)"` 展開成 `-p` 的引數**,agy 收到的就是檔案裡的內容
```bash
HOME=/tmp/task/home agy -p "$(cat /tmp/task_prompt.md)" --model gemini-3.8-flash-medium --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/agy.json 2> /tmp/agy.err; echo $? > /tmp/agy.exit
```

## bad example
- 同一份指示檔,但**用 `-p -` 加 stdin 重導向**;agy 收到的指示只有一個 `-`,exit 0,工作目錄沒有任何變更
```bash
HOME=/tmp/task/home agy -p - --model gemini-3.8-flash-medium --add-dir /project --mode accept-edits --output-format json --print-timeout 30m < /tmp/task_prompt.md > /tmp/agy.json 2> /tmp/agy.err; echo $? > /tmp/agy.exit
```

## good example
- 邊界:指示只有兩行,看起來不值得另存一個檔;**仍然先存成檔再用 `"$(cat …)"` 傳入**
```bash
# /tmp/task_prompt.md 的內容:
#   建立通知服務：process_event
#   請注意變數與引號
HOME=/tmp/task/home agy -p "$(cat /tmp/task_prompt.md)" --model gemini-3.8-flash-medium --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/agy.json 2> /tmp/agy.err; echo $? > /tmp/agy.exit
```

## bad example
- 邊界:同樣兩行指示,因為短就**直接打在命令列**;`\n` 不會變成換行,內容裡一有引號或 `$` 就會先被 shell 改掉
```bash
HOME=/tmp/task/home agy -p "建立通知服務：process_event\n請注意變數與引號" --model gemini-3.8-flash-medium --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/agy.json 2> /tmp/agy.err; echo $? > /tmp/agy.exit
```

# Rule 2 [must] - 指定工作目錄與模式
- 調用 `agy` 時必須使用 `--add-dir <dir>` 明確指定工作目錄路徑，並指定 `--mode accept-edits`
- 為什麼:未明確指定工作目錄或模式可能導致 agent 權限不足無法寫入目錄，或進入純規劃模式未實際產生代碼改動

## good example
- 明確指定 `--add-dir` 與 `--mode accept-edits`
```bash
HOME=/tmp/task/home agy -p "$(cat /tmp/task_prompt.md)" --model gemini-3.8-flash-medium --add-dir /home/user/repo --mode accept-edits --output-format json --print-timeout 30m > /tmp/agy.json 2> /tmp/agy.err; echo $? > /tmp/agy.exit
```

## bad example
- 缺少工作目錄與模式設定，預設環境可能限制寫入或未套用編輯
```bash
HOME=/tmp/task/home agy -p "$(cat /tmp/task_prompt.md)" --model gemini-3.8-flash-medium --output-format json --print-timeout 30m > /tmp/agy.json 2> /tmp/agy.err; echo $? > /tmp/agy.exit
```

# Rule 3 [must] - 輸出寫成 JSON、stderr 與結束碼三個紀錄檔
- 調用一律帶 `--output-format json`;stdout 重導向到 `agy.json`、stderr 重導向到 `agy.err`,指令最後接 `; echo $? > agy.exit` 把結束碼寫進 `agy.exit`;三個檔和任務指示檔放在同一個資料夾
- 為什麼:逾時與權限中止時 agy 回報的 `status` 都是 `SUCCESS`,回覆是空的或只有半句;要靠 JSON 的 `denied_actions` 與 stderr 的那一行才分得出是哪一種,文字模式只留下一個空的 stdout。`agy.exit` 出現才代表 agy 真的結束了;背景執行時太早去讀,`agy.json` 還是空的,會被當成失敗

## good example
- stdout、stderr 與結束碼**各寫進和指示檔同一個資料夾的 `agy.json`、`agy.err`、`agy.exit`**
```bash
HOME=/tmp/task/home agy -p "$(cat /tmp/task/task_prompt.md)" --model gemini-3.8-flash-medium --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

## bad example
- 同一次調用,但**沒有帶 `--output-format json`,輸出也沒有存檔**;agy 被切掉的時候畫面上什麼都沒有,看不出是逾時、被拒還是它真的沒有回覆
```bash
HOME=/tmp/task/home agy -p "$(cat /tmp/task/task_prompt.md)" --model gemini-3.8-flash-medium --add-dir /project --mode accept-edits --print-timeout 30m
```

## good example
- 邊界:stderr 平常是空的,看起來不值得存;**仍然寫進 `agy.err`**
```bash
HOME=/tmp/task/home agy -p "$(cat /tmp/task/task_prompt.md)" --model gemini-3.8-flash-medium --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

## bad example
- 邊界:同一次調用,JSON 有存,但**stderr 用 `2> /dev/null` 丟掉**;逾時的那一行 `print timeout after … with turn in progress` 只寫在 stderr,JSON 裡仍然是 `SUCCESS`
```bash
HOME=/tmp/task/home agy -p "$(cat /tmp/task/task_prompt.md)" --model gemini-3.8-flash-medium --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/task/agy.json 2> /dev/null; echo $? > /tmp/task/agy.exit
```

## good example
- 邊界:這次是前景執行,指令跑完就知道結束了,看起來不需要結束碼檔;**仍然接上 `; echo $? > agy.exit`**
```bash
HOME=/tmp/task/home agy -p "$(cat /tmp/task/task_prompt.md)" --model gemini-3.8-flash-medium --add-dir /project --mode accept-edits --output-format json --print-timeout 5m > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

## bad example
- 邊界:同一次調用,但**沒有寫 `agy.exit`**;判定調用結果時沒有東西可以證明 agy 已經結束,讀到的可能是寫到一半的 `agy.json`
```bash
HOME=/tmp/task/home agy -p "$(cat /tmp/task/task_prompt.md)" --model gemini-3.8-flash-medium --add-dir /project --mode accept-edits --output-format json --print-timeout 5m > /tmp/task/agy.json 2> /tmp/task/agy.err
```

# Rule 4 [must] - 一律指定時限,超過指令工具上限就放背景
- 調用一律帶 `--print-timeout`,值是使用者指定的時限;使用者沒有指定就用 `30m`
- 這個值超過呼叫端指令工具的時限(例如前景指令上限 10 分鐘)時,把整條指令放到背景執行,等 `agy.exit` 出現才算結束,再讀紀錄檔;不把值壓低去配合那個上限
- 為什麼:時限一到 agy 會直接切掉還在跑的回合,回覆是空的,改到一半的檔留在工作目錄;實測同一個任務跑了 7 分 45 秒與 8 分 33 秒,時限壓在 9 分鐘,第三次稍慢就被切掉,3 個檔改到一半

## good example
- 使用者沒有指定時限,呼叫端的前景指令上限是 10 分鐘;**帶 `--print-timeout 30m`,整條指令放到背景執行**
```bash
# 背景執行,等 agy.exit 出現後再讀 agy.json 與 agy.err
HOME=/tmp/task/home agy -p "$(cat /tmp/task/task_prompt.md)" --model gemini-3.8-flash-medium --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

## bad example
- 同一次調用,但**為了塞進 10 分鐘的前景上限,把時限壓成 `9m`**;任務跑到第 9 分鐘就被切掉
```bash
# 前景執行
HOME=/tmp/task/home agy -p "$(cat /tmp/task/task_prompt.md)" --model gemini-3.8-flash-medium --add-dir /project --mode accept-edits --output-format json --print-timeout 9m > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

## good example
- 邊界:使用者指定時限 5 分鐘,沒有超過 10 分鐘的前景上限;**照使用者給的 `5m`,前景執行**
```bash
# 前景執行
HOME=/tmp/task/home agy -p "$(cat /tmp/task/task_prompt.md)" --model gemini-3.8-flash-medium --add-dir /project --mode accept-edits --output-format json --print-timeout 5m > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

## bad example
- 邊界:同一個情況,覺得小任務很快就回來,就**不帶 `--print-timeout`**;agy 預設會一直等到回合結束,卡住的時候沒有東西會讓它停下來
```bash
# 前景執行
HOME=/tmp/task/home agy -p "$(cat /tmp/task/task_prompt.md)" --model gemini-3.8-flash-medium --add-dir /project --mode accept-edits --output-format json > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

# Rule 5 [must] - `--model` 照 pick_model.py 給的值
- 調用一律帶 `--model <值>`,值照抄 Phase 2 Step 1 的 `pick_model.py` 輸出的 `model`;不憑記憶或習慣自己選,也不改用 agy 裡的 Claude、GPT 模型
- `--kind` 依任務性質給:審查、驗收、第二意見給 `review`(預設 Argon),開發、重構、探索給 `dev`(Flash);`gemini-4-argon-7d` 剩不到 20%、stale 或 ai-quota 查不到時,腳本會把 `review` 也改成 Flash,照它的結果走
- 為什麼:2026-10-23 一次排 13 張審查全部固定 Argon,`gemini-4-argon-7d` 從 54% 用到 0%,之後要 Argon 的單向門審查全卡到重置;模型由腳本依額度決定,才不會每次都由呼叫端自己判斷而一路用到見底

## good example
- 審查任務,`pick_model.py --kind review` 因為 Argon 剩 1% 回了 Flash;**`--model` 照抄腳本的 `model`**
```bash
# pick_model.py 的輸出:{"kind": "review", "model": "gemini-3.8-flash-medium", "reason": "審查類預設 Argon,但 gemini-4-argon-7d 剩 1.0% 低於 20%,改用 Flash", ...}
HOME=/tmp/task/home agy -p "$(cat /tmp/task/task_prompt.md)" --model gemini-3.8-flash-medium --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

## bad example
- 同一個審查任務,記得「審查用 Argon」就**自己帶 `--model gemini-4-argon-high`**,沒有看腳本的結果;剩下的 1% 用完,這次與之後的 Argon 調用都回額度用完
```bash
HOME=/tmp/task/home agy -p "$(cat /tmp/task/task_prompt.md)" --model gemini-4-argon-high --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

## good example
- 邊界:開發任務,settings.json 的預設模型本來就是 Flash,看起來不帶 `--model` 也一樣;**仍然帶腳本給的 `--model`**
```bash
HOME=/tmp/task/home agy -p "$(cat /tmp/task/task_prompt.md)" --model gemini-3.8-flash-medium --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

## bad example
- 邊界:同一個開發任務,**省略 `--model`**;哪天有人改了全域預設,這次跑的就是別的模型,紀錄裡也看不出用了哪一個
```bash
HOME=/tmp/task/home agy -p "$(cat /tmp/task/task_prompt.md)" --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

# Rule 6 [must] - 同時最多 3 個 agy 調用,每批重查額度
- 要調用 agy 的任務不只一件時,分批進行,同一時間在跑的 agy 調用最多 3 個
- 一批全部出現 `agy.exit` 之後,下一批的每一個調用重新跑 `pick_model.py`,不沿用上一批的結果
- 為什麼:額度是跑完才扣的,一次排十幾個調用,第一個還沒回來,ai-quota 上的數字都還是開始前的;每批 3 個、每批重查,最多多燒一批就會被腳本攔下來改用 Flash

## good example
- 7 張 MR 要審;**分成 3、3、1 三批**,第二批開始前重跑 `pick_model.py`,發現 Argon 掉到 18% 就改用 Flash
```text
批 1:MR 101、102、103 → pick_model: gemini-4-argon-high(argon 剩 32%)
批 1 三個 agy.exit 都出現
批 2:MR 104、105、106 → 重跑 pick_model: gemini-3.8-flash-medium(argon 剩 18%)
批 3:MR 107 → 重跑 pick_model: gemini-3.8-flash-medium
```

## bad example
- 同樣 7 張 MR,**一次全部放到背景**,7 個都用一開始查到的 Argon;Argon 在第 4 個跑到一半時見底
```text
MR 101~107 同時開跑 → 全部用一開始的 pick_model 結果:gemini-4-argon-high(argon 剩 32%)
```

## good example
- 邊界:只有 2 張 MR 要審,不到 3 個;**一批跑完,沒有下一批就不必重查**
```text
批 1:MR 201、202 → pick_model: gemini-4-argon-high
```

## bad example
- 邊界:前一批剛跑完,覺得幾分鐘內額度不會變,**下一批沿用前一批的模型**;前一批的 3 個審查已經扣掉的額度沒有被看到
```text
批 1:MR 101、102、103 → pick_model: gemini-4-argon-high(argon 剩 32%)
批 2:MR 104、105、106 → 沿用 gemini-4-argon-high
```

# Rule 7 [must] - 只用 `-p`,不和 `--print` 一起寫
- 非互動調用只寫一次 `-p`,不加 `--print` 或 `--prompt`
- 為什麼:`-p`、`--print`、`--prompt` 在 agy 1.4.5 是同一個旗標(`agy --help`);同時寫兩個時,第二個會把後面的參數吃成指示,2026-10-23 出現過 `--model` 被當成任務指示、模型沒有套用的情形

## good example
- **只有一個 `-p`**,`--model` 照常生效
```bash
HOME=/tmp/task/home agy -p "$(cat /tmp/task/task_prompt.md)" --model gemini-3.8-flash-medium --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

## bad example
- 同一次調用,**`-p` 之外又加了 `--print`**;agy 收到兩次指示旗標,後面的參數被當成指示內容
```bash
HOME=/tmp/task/home agy --print -p "$(cat /tmp/task/task_prompt.md)" --model gemini-3.8-flash-medium --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

## good example
- 邊界:別支 Skill 的文件寫的是「執行 agy --print」;**照本 Skill 寫成 `-p`**
```bash
HOME=/tmp/task/home agy -p "$(cat /tmp/task/task_prompt.md)" --model gemini-3.8-flash-medium --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

## bad example
- 邊界:同一個情況,為了「兩份文件都照到」就**把 `--print` 與 `-p` 都寫上**
```bash
HOME=/tmp/task/home agy -p --print "$(cat /tmp/task/task_prompt.md)" --model gemini-3.8-flash-medium --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

# Rule 8 [must] - GitLab 身分只用 `GITLAB_PAT_AGY`
- 任務要 agy 對 GitLab 做事(留言、核准、開 MR)時,身分 token 只取環境變數 `GITLAB_PAT_AGY`,由 agy 從繼承的環境讀;調用前用 `[ -n "$GITLAB_PAT_AGY" ]` 確認有值
- 沒有值就停下,直接跳到回報,說明缺 `GITLAB_PAT_AGY`;不去 Vaultwarden 取、不改用別家的 `GITLAB_PAT_*`、不把 token 寫進任務指示檔
- 確認時只看有沒有值,不印出 token 本身
- 為什麼:agy 的審查與核准要以 agy 自己的 bot 帳號留下;換成別家的 token,核准會掛在別人名下或被 Self-Approval 擋掉。無頭的 agy 去 Vaultwarden 取值要互動解鎖,只會卡到逾時;寫進指示檔則 token 會留在紀錄檔裡

## good example
- **先確認 `GITLAB_PAT_AGY` 有值,再調用**;指示檔裡只寫「用環境變數 `GITLAB_PAT_AGY`」
```bash
[ -n "$GITLAB_PAT_AGY" ] || { echo "缺 GITLAB_PAT_AGY,停止調用" >&2; exit 1; }
HOME=/tmp/task/home agy -p "$(cat /tmp/task/task_prompt.md)" --model gemini-3.8-flash-medium --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

## bad example
- 同一個審查任務,`GITLAB_PAT_AGY` 沒有設,就**拿 `GITLAB_PAT_CLAUDE` 頂上**;核准掛在 Claude 名下,第二家審查的條件沒有成立
```bash
GITLAB_PAT_AGY="$GITLAB_PAT_CLAUDE" HOME=/tmp/task/home agy -p "$(cat /tmp/task/task_prompt.md)" --model gemini-3.8-flash-medium --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

## good example
- 邊界:任務只讀本機檔案、不碰 GitLab;**不需要 token,也不必檢查**
```bash
HOME=/tmp/task/home agy -p "$(cat /tmp/task/task_prompt.md)" --model gemini-3.8-flash-medium --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

## bad example
- 邊界:要核准 MR,`GITLAB_PAT_AGY` 沒有值,就**在指示檔裡叫 agy 自己去 Vaultwarden 取**;無頭的 agy 無法解鎖,一路等到 `--print-timeout`
```text
task_prompt.md:
  - Get the GitLab token from Vaultwarden (bw get password "GitLab PAT agy") and approve the MR.
```

# Rule 9 [must] - 以 prepare_home.py 建的家目錄調用
- 調用一律在前面加 `HOME=<prepare_home.py 輸出的 home>`,讓 agy 讀不到 `~/.gemini/config/mcp_config.json`
- 這個家目錄只有 agy 的 settings.json 與 `.gitconfig` 的複本,不連結回真正的家目錄;不要為了方便再手動把 `.ssh`、`.config` 等連進去
- 為什麼:agy 1.4.5 沒有停用 MCP 的調用旗標(`agy --help` 只有全域的 `agy mcp disable`);無頭模式下 agy 一去叫 gitlab MCP,工具權限是「詢問」,沒有人回答就被自動拒絕,整次調用判成權限中止。2026-10-23 實測:同一句「列出可用的 MCP」,用真正的家目錄回了 gitlab、kb 等 4 個伺服器,用 prepare_home.py 建的家目錄回 `NONE`,登入與允許清單照常可用;家目錄裡全是複本,agy 以 accept-edits 寫進 $HOME 的東西不會穿透到真正的家目錄

## good example
- **`HOME` 指向 prepare_home.py 建的家目錄**,agy 看不到任何 MCP 伺服器
