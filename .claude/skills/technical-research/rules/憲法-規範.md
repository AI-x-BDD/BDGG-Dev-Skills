# Rule 1 [must] - 憲法的條文和本 Skill 的規範都要照做
- 寫research.md 與 techstack.md時,`constitution_rules.py` 交回的每一條條文都照做;本 Skill 的規範沒有被條文點名取代的,也照樣照做
- 條文和本 Skill 的規範要求的是不同的事時,兩邊同時成立,不因為有了憲法就跳過本 Skill 的規範
- 為什麼:憲法是這個專案多加的要求,Skill 的規範是這份產出物能被下游讀懂的基本盤;只照其中一邊,交出的research.md 與 techstack.md不是違反憲法,就是讓下游的 Skill 讀不懂

## good example
- techstack 照憲法寫出確切版本,research 的實測**照 Skill 真的在這次執行過**
```
憲法:constitution/technical-research/techstack.md〈一覽表的每個技術寫出確切版本〉
Skill:rules/證據-規範.md〈標「實測」的證據要這次真的執行過〉

techstack.md:| 資料庫 | PostgreSQL 16.4 |
research.md R2 理由:- 實測:在暫存區以 docker 起 postgres:16.4,寫入 10 萬筆 timestamptz,查詢 p95 3 ms
```

## bad example
- 同一份產出,版本有寫,但**「實測」是憑印象寫的**,這次沒有執行過
```
techstack.md:| 資料庫 | PostgreSQL 16.4 |
research.md R2 理由:- 實測:PostgreSQL 查詢通常在幾毫秒內
```

# Rule 2 [must] - 沒有點名取代的衝突照本 Skill 的 Rule 做並交給使用者決定
- 條文和本 Skill 的某條 Rule 衝突、卻沒有用 `- 取代:` 點名它時,不自己選邊:research.md 與 techstack.md照本 Skill 的 Rule 寫,把衝突的條文與 Rule 列進研究摘要,由使用者決定要改憲法還是改產出物
- 為什麼:沒有點名的衝突,使用者沒有決定過要翻掉哪一條;AI 自己選了憲法,等於替使用者改了 Skill 的規範,選了 Skill 又沒說,使用者以為憲法有被照做

## good example
- 條文要研究項不寫替代方案,但替代方案是 Skill 樣板的固定段落;**照樣寫,把衝突寫進研究摘要**
```
憲法:constitution/technical-research/research.md〈研究項只寫結論〉(沒有取代)
Skill:樣板 research.template.md 的「考慮過的替代方案」段落

research.md R2:決策、理由、考慮過的替代方案三段都在
研究摘要:憲法〈研究項只寫結論〉和 research 樣板的固定段落衝突,先照樣板寫;要不要改憲法請你決定
```

## bad example
- 同一個衝突,**AI 自己選了憲法**,拿掉替代方案;`check_research.py` 判不過,摘要也沒提
```
research.md R2:只有決策與理由
研究摘要:(沒有提到衝突)
```
