# Rule 1 [must] - 只問會改變故事、需求或成功標準的問題
- 一個不確定處,它的答案會讓使用者故事、FR、NFR 或成功標準寫得不一樣,才問使用者
- 答案不會改變上述任何一項,或業界有通行的合理預設的,不問,把採用的預設寫進 spec.md 的「假設」
- 為什麼:問題太多,使用者會隨便選來打發,真正決定範圍的那幾題反而沒有被好好想過;該問的沒問,執行的人就自己替使用者決定了範圍,寫出來的規格看起來完整,做出來卻不是他要的

## good example
- 「照片從哪裡來」的答案**決定了匯入故事與「不動原檔」的需求**,所以問;支援哪些圖片格式有通行的預設,寫進假設
```
問:照片來源與原檔的處理方式?
  A. 本機資料夾,只建虛擬相簿,原檔完全不動(建議)
  B. 匯入時複製一份到應用程式自己的儲存空間
  C. 從雲端相簿服務同步

假設:支援的格式為常見的手機與相機照片格式(JPEG、PNG、HEIC);RAW 與影片不在第一版範圍內。
```

## bad example
- 同一份需求,但**把有通行預設的格式也拿來問**;使用者得多回答一題,答案也不會改變任何故事或需求
```
問:照片來源與原檔的處理方式?
  A. 本機資料夾,只建虛擬相簿,原檔完全不動(建議)
  B. 匯入時複製一份到應用程式自己的儲存空間
  C. 從雲端相簿服務同步

問:要支援哪些圖片格式?
  A. JPEG、PNG、HEIC(建議)
  B. 只支援 JPEG
```

## good example
- 邊界:「相簿名稱可以重複嗎」聽起來是小細節,但**答案會多出一條 FR(名稱唯一)與一個邊界情況**,所以要問
```
問:相簿名稱可以重複嗎?
  A. 不可重複;比對時忽略前後空白與英文大小寫,重複就阻止並提示改名(建議)
  B. 可以重複,以建立時間區分
```

## bad example
- 邊界:同一個不確定處,覺得是小細節就**自己決定、也沒寫進假設**;規格裡沒有名稱唯一的需求,使用者要到實際用了才發現兩本「2026 年 10 月」
```
(沒有問,也沒有寫進假設)

FR-005:系統必須讓使用者建立相簿。
```

# Rule 2 [must] - 每題附 2 到 4 個選項並標出建議
- 每一題列出 2 到 4 個互斥的選項,其中一個標上「(建議)」
- 為什麼:開放式的問題,使用者得自己想出所有可能,常常只回一句「你決定」;沒有建議,他不知道哪一個是考慮過取捨之後的預設,選項也可能被排成看起來一樣好

## good example
- **三個互斥的選項,第一個標了建議**,使用者看一眼就能選
```
問:自動分類的依據為何?
  A. 依拍攝日期,按月分組(建議)
  B. 依拍攝地點
  C. 依畫面內容辨識
```

## bad example
- 同一題,但**寫成開放式問題**;使用者得自己想有哪些分類方式
```
問:自動分類要依據什麼來分?
```

## good example
- 邊界:這一題只有兩種合理的做法,**列兩個選項也符合 2 到 4 個**,仍然標出建議
```
問:允許從哪些地方連進來,以及要不要登入?
  A. 只限家中內網(含 VPN 連回),不需要登入,不對外網公開(建議)
  B. 對外網公開,需要帳號密碼登入
```

## bad example
- 邊界:同一題列了選項,但**沒有標出建議**;兩個選項看起來一樣好,使用者不知道哪一個是考慮過的預設
```
問:允許從哪些地方連進來,以及要不要登入?
  A. 只限家中內網(含 VPN 連回),不需要登入,不對外網公開
  B. 對外網公開,需要帳號密碼登入
```

# Rule 3 [must] - 被推翻的回答在原題後註明修訂
- 後面的回答推翻或改寫了先前某一題的回答時,在先前那一題的回答後面註明是被哪一題修訂、修訂成什麼
- 原題的問與答保留,不刪除也不直接改寫
- 為什麼:直接改掉舊答案,讀規格的人看不出這個決定曾經變過、為什麼變;兩個答案都留著卻不註明,兩句互相矛盾,寫規格的人不知道該照哪一句

## good example
- 「執行形式」那一題把「本機」改成了伺服器,**原題的回答後面註明被哪一題修訂**
```
- 問:照片來源與原檔的處理方式? → 答:本機資料夾,只建虛擬相簿,原檔完全不動(「本機」後經「執行形式」一題修訂為家中伺服器上的資料夾)
- 問:這個應用程式要以什麼形式在哪裡執行? → 答:自架網頁應用程式,跑在家中伺服器(如 NAS),用瀏覽器開啟,照片資料夾位於伺服器上
```

## bad example
- 同樣兩題,但**原題的回答沒有註明**;一題說本機、一題說伺服器,讀的人不知道哪一個才算數
```
- 問:照片來源與原檔的處理方式? → 答:本機資料夾,只建虛擬相簿,原檔完全不動
- 問:這個應用程式要以什麼形式在哪裡執行? → 答:自架網頁應用程式,跑在家中伺服器(如 NAS),用瀏覽器開啟,照片資料夾位於伺服器上
```

## good example
- 邊界:後一題只是**補充**先前的回答(再次分類時拿哪些照片),沒有推翻它,所以原題不用註明
```
- 問:自動分類的依據為何? → 答:依拍攝日期(按月分組)
- 問:再次執行自動分類時拿哪些照片來分,建議名稱撞到既有相簿怎麼辦? → 答:只分類未加入任何相簿的照片;同名時預覽標示「將併入既有相簿」,確認後加入該相簿
```

## bad example
- 邊界:同樣是推翻,但**直接把原題的答案改成新的**;紀錄看起來很乾淨,但「本機」這個決定曾經存在、後來被改掉的事沒有留下來
```
- 問:照片來源與原檔的處理方式? → 答:家中伺服器上的資料夾,只建虛擬相簿,原檔完全不動
- 問:這個應用程式要以什麼形式在哪裡執行? → 答:自架網頁應用程式,跑在家中伺服器(如 NAS),用瀏覽器開啟,照片資料夾位於伺服器上
```
