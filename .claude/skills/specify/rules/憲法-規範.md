# Rule 1 [must] - 憲法的條文和本 Skill 的規範都要照做
- 寫spec.md時,`constitution_rules.py` 交回的每一條條文都照做;本 Skill 的規範沒有被條文點名取代的,也照樣照做
- 條文和本 Skill 的規範要求的是不同的事時,兩邊同時成立,不因為有了憲法就跳過本 Skill 的規範
- 為什麼:憲法是這個專案多加的要求,Skill 的規範是這份產出物能被下游讀懂的基本盤;只照其中一邊,交出的spec.md不是違反憲法,就是讓下游的 Skill 讀不懂

## good example
- 憲法要失敗情境、Skill 要 FR 放在所屬的故事;**兩邊都照做**
```
憲法:constitution/specify/spec.md〈每個使用者故事至少有一個失敗的驗收情境〉
Skill:rules/需求歸屬-規範.md〈只屬於一個故事的需求放在那個故事底下〉

### 使用者故事 1 - 加入品項
驗收情境:
1. 假如商品有庫存,當訪客按下「加入購物車」,則購物車數量加 1。
2. 假如這項商品已經有 99 件,當訪客再加一次,則畫面提示上限,數量不變。
功能需求:
- FR-002:同一項商品最多 99 件
```

## bad example
- 同一份 spec,失敗情境有寫,但**FR-002 被移到全域需求**;只照了憲法,Skill 的歸屬規範沒有人守
```
### 使用者故事 1 - 加入品項
驗收情境:
1. 假如商品有庫存,當訪客按下「加入購物車」,則購物車數量加 1。
2. 假如這項商品已經有 99 件,當訪客再加一次,則畫面提示上限,數量不變。
功能需求:無

## 全域需求
- FR-002:同一項商品最多 99 件
```

# Rule 2 [must] - 沒有點名取代的衝突照本 Skill 的 Rule 做並交給使用者決定
- 條文和本 Skill 的某條 Rule 衝突、卻沒有用 `- 取代:` 點名它時,不自己選邊:spec.md照本 Skill 的 Rule 寫,把衝突的條文與 Rule 列進規格摘要,由使用者決定要改憲法還是改產出物
- 為什麼:沒有點名的衝突,使用者沒有決定過要翻掉哪一條;AI 自己選了憲法,等於替使用者改了 Skill 的規範,選了 Skill 又沒說,使用者以為憲法有被照做

## good example
- 條文要全域需求不標故事,但沒有也不能點名取代;**照 Skill 標出適用的故事,把衝突寫進規格摘要**
```
憲法:constitution/specify/spec.md〈全域需求不標適用的故事〉(沒有取代)
Skill:rules/需求歸屬-規範.md〈全域需求只放跨越兩個以上故事的需求並標出適用的故事〉

spec.md
- FR-010:所有清單操作都要記錄操作者(適用:故事 1、故事 2)

規格摘要
- 憲法〈全域需求不標適用的故事〉和需求歸屬-規範衝突,spec.md 先照 Skill 標出適用的故事;要改憲法還是改 spec.md,請你決定
```

## bad example
- 同一個衝突,**AI 自己選了憲法**;全域需求沒有標故事,摘要也沒提,system-analysis 對不到需求出處
```
spec.md
- FR-010:所有清單操作都要記錄操作者

規格摘要
- (沒有提到衝突)
```
