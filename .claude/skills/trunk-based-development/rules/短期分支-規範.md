# Rule 1 [must] - 短期分支活不過兩天
- 短期分支壽命不得超過一至兩天
- 為什麼:分支會拉開開發者之間的距離;分支活得越久,變更離 trunk 越遠,合回時的衝突越大

## good example
- 早上開、**當天下午就合回**
```
10-06 09:30  git switch -c feat/todo-count
10-06 15:10  合回 main 並刪除 branch
```

## bad example
- 同一條 branch,但**活了 14 天**才合回
```
10-06 09:30  git switch -c feat/todo-count
10-20 16:00  合回 main 並刪除 branch
```

## good example
- 邊界:第二天結束時還沒有全部做完;**把已經可以上線的部分合回**,剩下的隔天從最新的 trunk 另開一條
```
10-06 09:30  git switch -c feat/todo-count
10-07 17:30  total 與 completed 已完成並通過建置,合回 main 並刪除 branch
10-08 09:30  git switch -c feat/todo-count-pending    # 從最新的 main 開
```

## bad example
- 邊界:同一個情況,想著再一天就做完,**把同一條 branch 留到第三天**
```
10-06 09:30  git switch -c feat/todo-count
10-08 17:00  合回 main 並刪除 branch
```

# Rule 2 [must] - 短期分支只供一人或一組 pair 使用
- 僅供單人(或一組 pair)開發使用
- 為什麼:多人共用的 branch 會變成另一條 trunk;大家的變更都先整合到它上面,離真正的 trunk 就越來越遠

## good example
- 這條 branch 上**只有一個人在提交**
```
feat/todo-count 的提交者:alice
```

## bad example
- 同一條 branch,但**隊友也 checkout 下來一起推**
```
feat/todo-count 的提交者:alice、bob、carol
```

## good example
- 邊界:有兩個人在提交,但**他們是同一組 pair**,輪流打字
```
feat/todo-count 的提交者:alice、bob(同一組 pair,輪流提交)
```

## bad example
- 邊界:同一組 pair 的 branch,**pair 以外的人順手推了一筆**;只是修一個錯字,但這條 branch 已經不只一個開發單位在用
```
feat/todo-count 的提交者:alice、bob(同一組 pair,輪流提交)、carol(順手修了一個錯字)
```

# Rule 3 [must] - 短期分支只和 trunk 互相合併
- 合併方向僅允許兩種:將 trunk 合進分支追上 HEAD,以及結束時合回 trunk
- 嚴禁合到別人的短期分支或合到 release 分支
- 為什麼:變更繞過 trunk 流到別的 branch,trunk 就不再是唯一的整合點;哪一條 branch 上有哪些變更,得一條一條查才知道

## good example
- 這條 branch **只和 `main` 往來**:先把 trunk 合進來,做完再合回去
```bash
git switch feat/todo-count
git merge origin/main                 # 把 trunk 合進來追上 HEAD
# 做完之後
git switch main
git merge --ff-only feat/todo-count   # 合回 trunk
git push origin main
git branch -d feat/todo-count
git push origin --delete feat/todo-count
```

## bad example
- 同一條 branch,但**合進了 `release/1.0`**
```bash
git switch release/1.0
git merge feat/todo-count
```

## good example
- 邊界:`feat/todo-export` 需要 alice 還沒合回的 `count_total()`;**等她把那一小步合回 trunk,再從 trunk 帶進來**
```bash
# alice 把 count_total() 合回 main 之後
git switch feat/todo-export
git merge origin/main
```

## bad example
- 邊界:同一個情況,**直接把 alice 的 branch 合進來**;沒有往她的 branch 推任何東西、看起來只是先借用,但這條 branch 已經帶著一段還沒進 trunk 的程式碼
```bash
git switch feat/todo-export
git merge origin/feat/todo-count
```

# Rule 4 [must] - 合回 trunk 後立刻刪除分支
- 合回後必須立刻刪除本機與 remote 分支
- 為什麼:留著的 branch 看不出合回了沒有;有人會繼續在上面提交,它就悄悄變成一條長期 branch

## good example
- 合回之後,**本機與 remote 的 branch 都刪掉**
```bash
git switch main && git merge --ff-only feat/todo-count && git push origin main
git branch -d feat/todo-count
git push origin --delete feat/todo-count
```

## bad example
- 同樣合回了,但 **branch 留著沒有刪**
```bash
git switch main && git merge --ff-only feat/todo-count && git push origin main
```

## good example
- 邊界:這次沒有走 PR,平台不會幫忙刪;**本機與 remote 兩邊都自己刪**
```bash
git switch main && git merge --ff-only feat/todo-count && git push origin main
git branch -d feat/todo-count
git push origin --delete feat/todo-count
```

## bad example
- 邊界:同樣的合回,**只刪了本機那一條**;本機看起來已經乾淨,remote 上的 branch 卻還在,隊友仍然看得到、拉得到
```bash
git switch main && git merge --ff-only feat/todo-count && git push origin main
git branch -d feat/todo-count
```
