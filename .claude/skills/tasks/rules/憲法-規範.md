# Rule 1 [must] - 憲法的條文和本 Skill 的規範都要照做
- 寫tasks.md時,`constitution_rules.py` 交回的每一條條文都照做;本 Skill 的規範沒有被條文點名取代的,也照樣照做
- 條文和本 Skill 的規範要求的是不同的事時,兩邊同時成立,不因為有了憲法就跳過本 Skill 的規範
- 為什麼:憲法是這個專案多加的要求,Skill 的規範是這份產出物能被下游讀懂的基本盤;只照其中一邊,交出的tasks.md不是違反憲法,就是讓下游的 Skill 讀不懂

## good example
- 憲法要預估時數,Skill 要 ⚙ 只列這個任務的元素;**兩邊都照做**
```
憲法:constitution/tasks/tasks.md〈每個任務標出預估時數〉
Skill:rules/任務-規範.md〈⚙ 只列這個任務做出來或測到的介面元素〉

- [ ] T012 [US1] 實作加入購物車 ⏱ 2h
  - ⚙ `contracts/openapi.yaml` § addCartItem
```

## bad example
- 同一個任務,時數有標,但**⚙ 列了整份 OpenAPI**;只照了憲法,implement 驗收時對不到這個任務的元素
```
- [ ] T012 [US1] 實作加入購物車 ⏱ 2h
  - ⚙ `contracts/openapi.yaml` § 全檔
```

# Rule 2 [must] - 沒有點名取代的衝突照本 Skill 的 Rule 做並交給使用者決定
- 條文和本 Skill 的某條 Rule 衝突、卻沒有用 `- 取代:` 點名它時,不自己選邊:tasks.md照本 Skill 的 Rule 寫,把衝突的條文與 Rule 列進提出任務清單時的問題,由使用者決定要改憲法還是改產出物
- 為什麼:沒有點名的衝突,使用者沒有決定過要翻掉哪一條;AI 自己選了憲法,等於替使用者改了 Skill 的規範,選了 Skill 又沒說,使用者以為憲法有被照做

## good example
- 條文要測試併進實作任務,但沒有也不能點名取代;**照 Skill 分開,把衝突放進提出任務清單時的問題**
```
憲法:constitution/tasks/tasks.md〈測試併進實作任務〉(沒有取代)
Skill:介面覆蓋表的實作欄與測試欄各要有任務(check_tasks.py 檢查)

tasks.md:T012 實作加入購物車、T013 測試加入購物車
提問:憲法〈測試併進實作任務〉和介面覆蓋的規定衝突,先照 Skill 分開;要不要改憲法請你決定
```

## bad example
- 同一個衝突,**AI 自己選了憲法**;介面覆蓋表的測試欄是空的,`check_tasks.py` 判不過,提問也沒提
```
tasks.md:T012 實作並測試加入購物車
提問:(沒有提到衝突)
```
