# Rule 1 [must] - 非互動執行必用 -p 模式
- 在 subshell、腳本或 automated agent 工具中調用時，必須使用 `-p`（非互動模式）參數，禁止裸調用 `copilot`
- 為什麼:裸調用 `copilot` 會啟動互動式全螢幕 TUI，在非互動或 headless 環境中會因缺乏 TTY 終端而無法繼續執行或掛起

## good example
- 使用非互動參數 `-p` 搭配重導向
```bash
copilot -p - --allow-all --no-ask-user -C . < /tmp/prompt.md
```

## bad example
- 裸調用 `copilot`，在非互動環境觸發 TUI 介面
```bash
copilot "請幫我修復購物車折扣計算 bug"
```

# Rule 2 [must] - 以檔案或 stdin 傳遞 prompt
- 傳遞給 `copilot` 的提示詞必須存成暫存檔並以 stdin 重導向傳入（如 `-p - < /path/to/prompt.md`），禁止在 shell 命令列以字串參數直接傳入多行 prompt
- 為什麼:多行提示詞直接傳入 shell 命令列容易被引號、換行符號或變數擴展破壞，造成指令解析語法錯誤

## good example
- 將 prompt 存為檔案後透過 stdin 導向傳給 `copilot`
```bash
copilot -p - --allow-all --no-ask-user -C /project < /tmp/task_prompt.md
```

## bad example
- 在命令列以多行字串直接作為 prompt 參數傳入
```bash
copilot -p "修復邊界計算：calculate_discount\n請檢查 $TOTAL 與 item.price 的型別" --allow-all
```

# Rule 3 [must] - 明確開啟自動權限與禁用提問
- 非互動調用 `copilot` 時必須明確傳入 `--allow-all`（或 `--allow-all-tools`）與 `--no-ask-user` 參數
- 為什麼:未傳入全授權與禁用提問參數時，Copilot 在調用工具或遇到不確定情境時會等待使用者在終端確認或回答問題，導致無人值守的自動化流程卡住超時

## good example
- 同時傳入 `--allow-all` 與 `--no-ask-user`
```bash
copilot -p - --allow-all --no-ask-user -C /project < /tmp/task_prompt.md
```

## bad example
- 未配置自動授權與禁用提問，導致工具執行或提問時等待終端互動
```bash
copilot -p - -C /project < /tmp/task_prompt.md
```

# Rule 4 [must] - 指定工作目錄與無色輸出
- 調用 `copilot` 時必須使用 `-C <dir>` 明確指定工作目錄路徑，並傳入 `--no-color`
- 為什麼:未明確指定工作目錄可能導致 agent 寫錯路徑；未停用顏色輸出時，ANSI 控制碼會混入輸出日誌，增加後續解析失敗的風險

## good example
- 明確指定 `-C` 與 `--no-color`
```bash
copilot -p - --allow-all --no-ask-user -C /home/user/repo --no-color < /tmp/task_prompt.md
```

## bad example
- 缺少工作目錄與顏色控制，依賴當前目錄且夾帶終端跳脫碼
```bash
copilot -p - --allow-all --no-ask-user < /tmp/task_prompt.md
```

# Rule 5 [must] - 調用前確認 git baseline
- 在執行 `copilot` 前，必須先執行 `git status --porcelain` 確認或記錄當前工作區狀態，確保無未預期的未追蹤或未提交改動
- 為什麼:調用前工作區若處於不乾淨狀態，調用完成後無法透過 `git diff` 清楚辨別哪些變更是 Copilot 產生的，導致驗收失去基準

## good example
- 調用前先檢查工作區並確認乾淨基準
```bash
git status --porcelain
copilot -p - --allow-all --no-ask-user -C /project --no-color < /tmp/task_prompt.md
git diff
```

## bad example
- 調用前未檢查 git 狀態即直接執行，無法分辨變更來源
```bash
copilot -p - --allow-all --no-ask-user -C /project --no-color < /tmp/task_prompt.md
git diff
```
