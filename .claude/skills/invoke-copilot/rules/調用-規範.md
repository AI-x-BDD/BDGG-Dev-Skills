# Rule 1 [must] - 非互動執行必用 -p 模式
- 在 subshell、腳本或 automated agent 工具中調用時，必須使用 `-p`（非互動模式）參數，禁止裸調用 `copilot`
- 為什麼:裸調用 `copilot` 會啟動互動式全螢幕 TUI，在非互動或 headless 環境中會因缺乏 TTY 終端而無法繼續執行或掛起

## good example
- 使用非互動參數 `-p`
```bash
copilot -p "$(cat /tmp/task/task_prompt.md)" -C /project --no-ask-user --no-color --allow-tool 'write' --allow-tool 'shell(python3:*)' --output-format json > /tmp/task/copilot.jsonl 2> /tmp/task/copilot.err; echo $? > /tmp/task/copilot.exit
```

## bad example
- 裸調用 `copilot`，在非互動環境觸發 TUI 介面
```bash
copilot "請幫我修復購物車折扣計算 bug"
```

# Rule 2 [must] - 任務指示檔以 `-p "$(cat 檔)"` 傳入
- 任務指示先存成檔,調用時用 `-p "$(cat <指示檔路徑>)"` 把全文當成 `-p` 的引數
- 禁止 `-p - < 檔`,也禁止把指示內容直接打在命令列
- 為什麼:copilot 的 `-p` 把後面那個引數當成指示本身,不讀 stdin;`-p - < 檔` 會讓 copilot 只收到一個 `-`,exit 0,回覆是 `No actionable task was provided.`(實測 3 次都是)。把內容直接打在命令列,引號、換行與 `$` 會先被 shell 改掉

## good example
- 指示檔的全文**由 `"$(cat …)"` 展開成 `-p` 的引數**,copilot 收到的就是檔案裡的內容
```bash
copilot -p "$(cat /tmp/task/task_prompt.md)" -C /project --no-ask-user --no-color --allow-tool 'write' --allow-tool 'shell(python3:*)' --output-format json > /tmp/task/copilot.jsonl 2> /tmp/task/copilot.err; echo $? > /tmp/task/copilot.exit
```

## bad example
- 同一份指示檔,但**用 `-p -` 加 stdin 重導向**;copilot 收到的指示只有一個 `-`,exit 0,工作目錄沒有任何變更
```bash
copilot -p - -C /project --no-ask-user --no-color --allow-tool 'write' --allow-tool 'shell(python3:*)' --output-format json < /tmp/task/task_prompt.md > /tmp/task/copilot.jsonl 2> /tmp/task/copilot.err; echo $? > /tmp/task/copilot.exit
```

## good example
- 邊界:指示只有兩行,看起來不值得另存一個檔;**仍然先存成檔再用 `"$(cat …)"` 傳入**
```bash
# /tmp/task/task_prompt.md 的內容:
#   修復邊界計算：calculate_discount
#   請檢查 $TOTAL 與 item.price 的型別
copilot -p "$(cat /tmp/task/task_prompt.md)" -C /project --no-ask-user --no-color --allow-tool 'write' --allow-tool 'shell(python3:*)' --output-format json > /tmp/task/copilot.jsonl 2> /tmp/task/copilot.err; echo $? > /tmp/task/copilot.exit
```

## bad example
- 邊界:同樣兩行指示,因為短就**直接打在命令列**;`\n` 不會變成換行,`$TOTAL` 會先被 shell 展開成空字串
```bash
copilot -p "修復邊界計算：calculate_discount\n請檢查 $TOTAL 與 item.price 的型別" -C /project --no-ask-user --no-color --allow-tool 'write' --allow-tool 'shell(python3:*)' --output-format json > /tmp/task/copilot.jsonl 2> /tmp/task/copilot.err; echo $? > /tmp/task/copilot.exit
```

# Rule 3 [must] - 只開任務需要的工具權限並禁用提問
- 調用一律帶 `--no-ask-user`
- 任務要改檔才加 `--allow-tool 'write'`;任務指示檔裡要 Copilot 跑的每一種 shell 指令,各加一個 `--allow-tool 'shell(<指令>:*)'`
- 不用 `--allow-all`、`--allow-all-tools`、`--yolo`
- 為什麼:全開的旗標會被呼叫端的權限檢查擋下(實測在 Claude Code 裡整條指令被拒,copilot 一次都沒有被呼叫);沒被允許的工具 Copilot 會收到 denied 然後繼續做,不會卡住等人回答

## good example
- 任務要改檔並跑 `python3 -m unittest`;**只開 `write` 與 `python3` 兩項**
```bash
copilot -p "$(cat /tmp/task/task_prompt.md)" -C /project --no-ask-user --no-color --allow-tool 'write' --allow-tool 'shell(python3:*)' --output-format json > /tmp/task/copilot.jsonl 2> /tmp/task/copilot.err; echo $? > /tmp/task/copilot.exit
```

## bad example
- 同一個任務,但**用 `--allow-all` 全開**;在有權限檢查的呼叫端這條指令會整條被擋
```bash
copilot -p "$(cat /tmp/task/task_prompt.md)" -C /project --no-ask-user --no-color --allow-all --output-format json > /tmp/task/copilot.jsonl 2> /tmp/task/copilot.err; echo $? > /tmp/task/copilot.exit
```

## good example
- 邊界:任務是審查一份 diff,只讀不改;**不給 `write`,只開讀 diff 要用的 `git`**
```bash
copilot -p "$(cat /tmp/task/task_prompt.md)" -C /project --no-ask-user --no-color --allow-tool 'shell(git:*)' --output-format json > /tmp/task/copilot.jsonl 2> /tmp/task/copilot.err; echo $? > /tmp/task/copilot.exit
```

## bad example
- 邊界:同一個審查任務,想著以防萬一就**順手加上 `--allow-tool 'write'`**;審查者因此能改檔,任務並沒有要它改
```bash
copilot -p "$(cat /tmp/task/task_prompt.md)" -C /project --no-ask-user --no-color --allow-tool 'write' --allow-tool 'shell(git:*)' --output-format json > /tmp/task/copilot.jsonl 2> /tmp/task/copilot.err; echo $? > /tmp/task/copilot.exit
```

# Rule 4 [must] - 指定工作目錄與無色輸出
- 調用 `copilot` 時必須使用 `-C <dir>` 明確指定工作目錄路徑，並傳入 `--no-color`
- 為什麼:未明確指定工作目錄可能導致 agent 寫錯路徑；未停用顏色輸出時，ANSI 控制碼會混入輸出日誌，增加後續解析失敗的風險

## good example
- 明確指定 `-C` 與 `--no-color`
```bash
copilot -p "$(cat /tmp/task/task_prompt.md)" -C /home/user/repo --no-ask-user --no-color --allow-tool 'write' --allow-tool 'shell(python3:*)' --output-format json > /tmp/task/copilot.jsonl 2> /tmp/task/copilot.err; echo $? > /tmp/task/copilot.exit
```

## bad example
- 缺少工作目錄與顏色控制，依賴當前目錄且夾帶終端跳脫碼
```bash
copilot -p "$(cat /tmp/task/task_prompt.md)" --no-ask-user --allow-tool 'write' --allow-tool 'shell(python3:*)' --output-format json > /tmp/task/copilot.jsonl 2> /tmp/task/copilot.err; echo $? > /tmp/task/copilot.exit
```

# Rule 5 [must] - 調用前確認 git baseline
- 在執行 `copilot` 前，必須先執行 `git status --porcelain` 確認或記錄當前工作區狀態，確保無未預期的未追蹤或未提交改動
- 為什麼:調用前工作區若處於不乾淨狀態，調用完成後無法透過 `git diff` 清楚辨別哪些變更是 Copilot 產生的，導致驗收失去基準

## good example
- 調用前先檢查工作區並確認乾淨基準
```bash
git status --porcelain
copilot -p "$(cat /tmp/task/task_prompt.md)" -C /project --no-ask-user --no-color --allow-tool 'write' --allow-tool 'shell(python3:*)' --output-format json > /tmp/task/copilot.jsonl 2> /tmp/task/copilot.err; echo $? > /tmp/task/copilot.exit
git diff
```

## bad example
- 調用前未檢查 git 狀態即直接執行，無法分辨變更來源
```bash
copilot -p "$(cat /tmp/task/task_prompt.md)" -C /project --no-ask-user --no-color --allow-tool 'write' --allow-tool 'shell(python3:*)' --output-format json > /tmp/task/copilot.jsonl 2> /tmp/task/copilot.err; echo $? > /tmp/task/copilot.exit
git diff
```

# Rule 6 [must] - 輸出寫成 JSONL、stderr 與結束碼三個紀錄檔
- 調用一律帶 `--output-format json`;stdout 重導向到 `copilot.jsonl`、stderr 重導向到 `copilot.err`,指令最後接 `; echo $? > copilot.exit` 把結束碼寫進 `copilot.exit`;三個檔和任務指示檔放在同一個資料夾
- 為什麼:Copilot 沒收到指示或沒做事時一樣是 exit 0,文字輸出只有一句話;要靠 JSONL 最後一筆 `result` 事件與被拒的工具事件才看得出這次調用有沒有做完。`copilot.exit` 出現才代表 Copilot 真的結束了,太早去讀會讀到寫到一半的 JSONL

## good example
- stdout、stderr 與結束碼**各寫進和指示檔同一個資料夾的 `copilot.jsonl`、`copilot.err`、`copilot.exit`**
```bash
copilot -p "$(cat /tmp/task/task_prompt.md)" -C /project --no-ask-user --no-color --allow-tool 'write' --allow-tool 'shell(python3:*)' --output-format json > /tmp/task/copilot.jsonl 2> /tmp/task/copilot.err; echo $? > /tmp/task/copilot.exit
```

## bad example
- 同一次調用,但**沒有帶 `--output-format json`,輸出也沒有存檔**;Copilot 空手而回的時候畫面上只有一句話,看不出它有沒有做事、有沒有工具被拒
```bash
copilot -p "$(cat /tmp/task/task_prompt.md)" -C /project --no-ask-user --no-color --allow-tool 'write' --allow-tool 'shell(python3:*)'
```

## good example
- 邊界:這次是前景執行,指令跑完就知道結束了,看起來不需要結束碼檔;**仍然接上 `; echo $? > copilot.exit`**
```bash
copilot -p "$(cat /tmp/task/task_prompt.md)" -C /project --no-ask-user --no-color --allow-tool 'write' --allow-tool 'shell(python3:*)' --output-format json > /tmp/task/copilot.jsonl 2> /tmp/task/copilot.err; echo $? > /tmp/task/copilot.exit
```

## bad example
- 邊界:同一次調用,但**沒有寫 `copilot.exit`**;判定調用結果時沒有東西可以證明 Copilot 已經結束,讀到的可能是寫到一半的 JSONL
```bash
copilot -p "$(cat /tmp/task/task_prompt.md)" -C /project --no-ask-user --no-color --allow-tool 'write' --allow-tool 'shell(python3:*)' --output-format json > /tmp/task/copilot.jsonl 2> /tmp/task/copilot.err
```
