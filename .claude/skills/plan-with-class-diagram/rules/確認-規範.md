# Rule 1 [must] - 明確同意進入開發才算確認
- 只有使用者明確說可以進入開發,才進入 Phase 2
- 使用者提問、只評論某一處、或同意方向但要求改動,都不算確認
- 類別圖改過之後,先前的同意不算數,要把改完的圖重新提出再問一次
- 為什麼:Phase 2 會開始改檔;使用者沒有對最後那張圖說可以就動手,他同意的就不是實際做出來的設計

## good example
- 使用者回的是一個問題;**回答之後再問一次,等到明確的同意**
```
1. 提出類別圖,問「可以照這張圖進入開發嗎?」
2. 使用者:「OrderService 為什麼要直接相依 InventoryChecker?」
3. 回答這個問題,再問一次「可以照這張圖進入開發嗎?」,等使用者回答。
```

## bad example
- 同一段對話,但**把提問當成沒有反對**,回答完就動手
```
1. 提出類別圖,問「可以照這張圖進入開發嗎?」
2. 使用者:「OrderService 為什麼要直接相依 InventoryChecker?」
3. 回答這個問題,接著開始實作 InventoryChecker。
```

## good example
- 邊界:使用者同意方向但要求改動;**改完的圖重新提出,再問一次**
```
1. 提出類別圖,問「可以照這張圖進入開發嗎?」
2. 使用者:「方向可以,但 InventoryChecker 不要直接相依 StockRepository,中間加一個 interface。」
3. 回到 Phase 1 Step 4,把加了 StockReader 的類別圖重新提出,再問一次「可以照這張圖進入開發嗎?」
```

## bad example
- 邊界:同一段對話,使用者確實說了「方向可以」,但**那句話是對改動之前的圖說的**;加了 StockReader 的那張圖,使用者沒看過
```
1. 提出類別圖,問「可以照這張圖進入開發嗎?」
2. 使用者:「方向可以,但 InventoryChecker 不要直接相依 StockRepository,中間加一個 interface。」
3. 把 StockReader 加進類別圖,因為使用者已經說過方向可以,直接開始實作。
```
