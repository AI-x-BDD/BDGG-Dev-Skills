# Rule 1 [must] - 類別、對外成員、關係變了才算偏離類別圖
- 實作時要做的事和使用者確認過的類別圖不一樣,依下表判定算不算偏離

| 情況 | 算不算偏離 |
|---|---|
| 多了或少了類別 | 算 |
| 對外成員變了:public 方法或屬性的增減、改名,或參數、回傳型別和圖上不同 | 算 |
| 關係變了:多了或少了一條關係,或種類、方向和圖上不同 | 算 |
| private 成員的增減 | 不算 |

- 為什麼:類別圖上畫的類別、對外成員與關係,就是使用者確認過的範圍,這三樣變了還繼續做,做出來的就不是他同意的設計;private 成員圖上本來就不畫,連它也算偏離,每一次內部調整都得停下來重新確認

## good example
- 需要一個圖上沒有的類別,**判定為偏離,停下實作回去重新提圖**
```
類別圖的關係:
    OrderService --> InventoryChecker
    InventoryChecker --> StockRepository

1. 實作 InventoryChecker 時,發現每次都查庫存太慢,需要一個 StockCache 類別。
2. 類別圖上沒有 StockCache,算偏離;停下實作,跳至 Phase 1 Step 2,把 StockCache 加進類別圖重新提出。
```

## bad example
- 同一個情況,但**直接把圖上沒有的類別做出來**;使用者確認過的那張圖裡沒有 StockCache
```
類別圖的關係:
    OrderService --> InventoryChecker
    InventoryChecker --> StockRepository

1. 實作 InventoryChecker 時,發現每次都查庫存太慢,需要一個 StockCache 類別。
2. 新增 StockCache 並讓 InventoryChecker 使用它,接著實作 OrderService。
```

## good example
- 圖上 `OrderService` 只連到 `InventoryChecker`;要多一條關係,**判定為偏離,停下實作回去重新提圖**
```
類別圖的關係:
    OrderService --> InventoryChecker
    InventoryChecker --> StockRepository

1. 實作 OrderService 時,想直接向 StockRepository 查數量,好在錯誤訊息裡帶上庫存。
2. 類別圖上沒有 OrderService --> StockRepository 這條關係,算偏離;停下實作,跳至 Phase 1 Step 2。
```

## bad example
- 同一個情況,類別一個也沒多,但**多了一條圖上沒有的關係**還繼續做
```
類別圖的關係:
    OrderService --> InventoryChecker
    InventoryChecker --> StockRepository

1. 實作 OrderService 時,想直接向 StockRepository 查數量,好在錯誤訊息裡帶上庫存。
2. 在 OrderService 加一個 StockRepository 欄位,繼續實作。
```

## good example
- 邊界:多了一個方法,但它是 **private,圖上本來就不畫**,對外的 `isAvailable` 沒有變,不算偏離,直接做
```
類別圖上的 InventoryChecker:
    +isAvailable(Cart cart) bool

實作出來的 InventoryChecker:
    +isAvailable(Cart cart) bool
    -sumQuantity(Cart cart) int

處理:不算偏離,繼續實作下一個類別。
```

## bad example
- 邊界:同一個方法、同樣只是為了整理計算,但**寫成 public**;它成了圖上沒有的對外成員,卻被當成內部調整繼續做
```
類別圖上的 InventoryChecker:
    +isAvailable(Cart cart) bool

實作出來的 InventoryChecker:
    +isAvailable(Cart cart) bool
    +sumQuantity(Cart cart) int

處理:不算偏離,繼續實作下一個類別。
```
