# Rule 1 [must] - 憲法的條文和本 Skill 的規範都要照做
- 寫plan.md時,`constitution_rules.py` 交回的每一條條文都照做;本 Skill 的規範沒有被條文點名取代的,也照樣照做
- 條文和本 Skill 的規範要求的是不同的事時,兩邊同時成立,不因為有了憲法就跳過本 Skill 的規範
- 為什麼:憲法是這個專案多加的要求,Skill 的規範是這份產出物能被下游讀懂的基本盤;只照其中一邊,交出的plan.md不是違反憲法,就是讓下游的 Skill 讀不懂

## good example
- 憲法要寫出負責團隊,Skill 要外部系統各自成一個端點;**兩邊都照做**
```
憲法:constitution/system-analysis/plan.md〈每個端點寫出負責的團隊〉
Skill:rules/端點-規範.md〈外部系統各自成一個端點〉

E2 後端(Fastify):負責團隊 平台組
E3 金流(綠界):負責團隊 平台組
```

## bad example
- 同一份 plan,團隊有寫,但**金流被併進後端**;只照了憲法,Skill 的端點規範沒有人守
```
E2 後端(Fastify,含綠界金流):負責團隊 平台組
```

# Rule 2 [must] - 沒有點名取代的衝突照本 Skill 的 Rule 做並交給使用者決定
- 條文和本 Skill 的某條 Rule 衝突、卻沒有用 `- 取代:` 點名它時,不自己選邊:plan.md照本 Skill 的 Rule 寫,把衝突的條文與 Rule 列進提出分析波段時的問題,由使用者決定要改憲法還是改產出物
- 為什麼:沒有點名的衝突,使用者沒有決定過要翻掉哪一條;AI 自己選了憲法,等於替使用者改了 Skill 的規範,選了 Skill 又沒說,使用者以為憲法有被照做

## good example
- 條文要把第三方併進後端,但沒有也不能點名取代;**照 Skill 分開,把衝突放進提出波段時的問題**
```
憲法:constitution/system-analysis/plan.md〈第三方服務併進呼叫它的端點〉(沒有取代)
Skill:rules/端點-規範.md〈外部系統各自成一個端點〉

plan.md:E2 後端、E3 金流 各自一個端點
提問:憲法〈第三方服務併進呼叫它的端點〉和端點-規範衝突,先照 Skill 分開;要改憲法還是改 plan.md,請你決定
```

## bad example
- 同一個衝突,**AI 自己選了憲法**;金流沒有自己的端點,也就沒有 planner 去分析它的介面
```
plan.md:E2 後端(含金流)
提問:(沒有提到衝突)
```
