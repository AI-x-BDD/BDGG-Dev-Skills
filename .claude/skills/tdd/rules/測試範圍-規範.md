# Rule 1 [must] - 綠燈與小步跑任務的測試檔,前後跑全部,範圍不自己挑
- 紅燈只跑剛寫的那一支;綠燈與重構的每一小步跑「任務的測試檔」:呼叫方的指示或任務描述寫到的測試檔;兩處都沒有寫時,改跑快速層
- 重構開始前與最後一步之後跑「全部」;呼叫方可以把「全部」指定成另一條指令(例如 implement 的端點 subagent 把它指定成快速層,全部留給主 agent 合併後跑)
- 快速層與全部的指令依序取自呼叫方的指示、`testplan.md` § 測試指令;兩處都沒有時,兩層都跑專案的完整測試指令
- 不在這些來源之外,自己把「看起來相關」的測試檔加進範圍
- 為什麼:colab-gpu-bridge 002 的 E2 subagent 把一支 98 個真瀏覽器測試的檔算成相關,每個紅綠任務等 110 秒,61% 的時間在等測試;E8 只跑任務寫到的兩支整合測試,一次 0.2 到 13 秒。反過來,每個綠燈都跑整層快速層,這個專案也要 139 秒

## good example
- 任務描述寫到 `tests/integration/test_model_library.py`;**綠燈只跑這一支**,重構前後才跑全部
```
🟢 T005b 綠燈:uv run pytest tests/integration/test_model_library.py -q   112 passed in 0.4s
🔵 T027 重構前:uv run pytest -q   (背景執行)628 passed
```

## bad example
- 同一個任務,**自己把「直接用到改動檔的測試檔」也加進來**,其中一支是真瀏覽器的 e2e;每個綠燈都多等了將近兩分鐘
```
🟢 T031b 綠燈:uv run pytest tests/integration/test_api_library.py tests/e2e/test_locale.py   112 秒
```

## good example
- 邊界:呼叫方(implement 的端點指示)寫明「要跑全部的地方改跑快速層」;**重構前後照呼叫方的指令跑快速層**,小步仍然只跑任務的測試檔
```
端點指示:快速層 uv run pytest tests/integration -q --deselect …;要跑全部的地方改跑這條
🔵 T027 重構前:快速層 446 passed in 139s
🔵 T027 第 1 小步:uv run pytest tests/integration/test_model_library.py -q   136 passed in 0.5s
🔵 T027 重構後:快速層 446 passed in 140s
```

## bad example
- 邊界:同一個重構,因為「快速層比全部快很多」就**每一小步都跑快速層**;四小步多等了將近十分鐘,任務的測試檔一秒就能給的回饋被拖成兩分鐘
```
🔵 T027 第 1 小步:快速層 446 passed in 139s
🔵 T027 第 2 小步:快速層 446 passed in 141s
```

# Rule 2 [must] - 跑全部時用背景執行等完成通知
- 全部測試預期會超過工具的前景時限時,用背景執行,等完成的通知再讀結果;等待時不寫輪詢的迴圈,也不在中途重跑另一份
- 同一個工作區同一時間只跑一份全部測試
- 為什麼:前景執行到時限就被切斷,看起來像測試失敗,只好重跑;寫迴圈輪詢會在結果出來前一直佔著回合。colab-gpu-bridge 002 有 4 次全部測試的前景執行停在 180 秒,E8 有 32 分鐘在等背景測試

## good example
- 全部約 6 分鐘;**背景執行,等通知再讀結果**
```
$ uv run pytest -q > /tmp/full.txt 2>&1      (背景執行)
(收到完成通知)
$ tail -1 /tmp/full.txt
628 passed, 21 deselected in 350.45s
```

## bad example
- 同一次執行,**在前景跑**;到時限被切斷,只看到前半段的輸出,又重跑一次
```
$ uv run pytest -q
........................  (180 秒後被切斷)
$ uv run pytest -q
```

## good example
- 邊界:全部只要 20 秒,不會超過前景時限;**直接在前景跑**,不必改背景
```
$ uv run pytest -q
48 passed in 19.8s
```

## bad example
- 邊界:同一個 20 秒的全部,還是**改成背景執行再寫迴圈每 5 秒查一次**;多出好幾個回合,等的時間比測試本身還長
```
$ uv run pytest -q > /tmp/full.txt 2>&1 &
$ until grep -q passed /tmp/full.txt; do sleep 5; done
```
