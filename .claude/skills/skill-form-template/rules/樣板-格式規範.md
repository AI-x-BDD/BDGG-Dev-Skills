# Rule 1 [must] - 一份樣板由骨架與範例兩個檔組成
- 骨架是執行的人複製之後拿來改寫的檔;範例是同一份骨架填完之後的一個具體結果
- 兩個檔缺一個,這份樣板就還沒寫完
- 為什麼:只有骨架,執行的人不知道填位符號填完該長什麼樣子;只有範例,他分不出哪些字是固定的、哪些是那個案例才有的

## good example
- **骨架與範例都在**,執行的人複製第一個、對照第二個
```
templates/
├── class-diagram.mmd           ← 骨架
└── class-diagram.example.mmd   ← 範例
```

## bad example
- 同一份樣板,但**只寫了骨架**;`{{…}}` 填完該長什麼樣子,沒有地方可以對照
```
templates/
└── class-diagram.mmd           ← 骨架
```

# Rule 2 [must] - 骨架與範例照固定路徑命名
- 兩個檔都放在目標 skill 的 `templates/` 底下,路徑如下

```
<skill-package>/templates/<樣板名字>.<格式>            ← 骨架
<skill-package>/templates/<樣板名字>.example.<格式>    ← 範例
```

- `<格式>` 是那份產出內容的副檔名;兩個檔的 `<樣板名字>` 與 `<格式>` 相同,範例只在 `<格式>` 之前多一段 `.example`
- 為什麼:SOP 的步驟是用這兩個路徑點名樣板的;名字對不上,執行的人看不出哪兩個檔是一對,副檔名不在最後,編輯器也認不出它的格式

## good example
- 兩個檔**同名、同副檔名**,範例只多了 `.example`
```
templates/
├── class-diagram.mmd
└── class-diagram.example.mmd
```

## bad example
- 同一份樣板,但**範例另取了名字**;目錄裡的樣板一多,看不出它是哪一個骨架的範例
```
templates/
├── class-diagram.mmd
└── order-service-sample.mmd
```

## good example
- 邊界:`.example` 夾在名字與副檔名之間,**檔名仍以 `.mmd` 結尾**
```
templates/
├── class-diagram.mmd
└── class-diagram.example.mmd
```

## bad example
- 邊界:一樣同名、一樣有 `example`,但**接在副檔名後面**;這個檔不再是 `.mmd`,編輯器與預覽都不會把它當成 Mermaid
```
templates/
├── class-diagram.mmd
└── class-diagram.mmd.example
```

# Rule 3 [must] - 骨架整個檔案就是樣板
- 骨架從第一行到最後一行都是要被複製的內容,複製之後只需要改寫填位符號
- 使用說明、填寫提示這類不屬於產出的文字,不寫進骨架
- 為什麼:執行的人是整個檔複製過去再改的,夾在裡面的說明會跟著留在產出裡

## good example
- `templates/class-diagram.mmd` 的全部內容;**每一行複製過去都是類別圖的一部分**
```
classDiagram
    class {{類別名稱}} {
        +{{方法名稱}}({{參數型別}} {{參數名稱}}) {{回傳型別}}
    }
    {{相依的類別}} --> {{被相依的類別}}
```

## bad example
- 同一份骨架,但**前面多了標題與使用說明,圖還包在 code fence 裡**;整個檔複製過去,產出就不是合法的 `.mmd`
````
# 類別圖樣板
請把下面每個 `{{…}}` 換成實際內容,類別有幾個就重複幾次。

```mermaid
classDiagram
    class {{類別名稱}} {
        +{{方法名稱}}({{參數型別}} {{參數名稱}}) {{回傳型別}}
    }
    {{相依的類別}} --> {{被相依的類別}}
```
````

## good example
- 邊界:`classDiagram` 這一行不是填位符號,但**它是每一份產出都要有的固定內容**,屬於樣板
```
classDiagram
    class {{類別名稱}} {
        +{{方法名稱}}({{參數型別}} {{參數名稱}}) {{回傳型別}}
    }
    {{相依的類別}} --> {{被相依的類別}}
```

## bad example
- 邊界:多出來的兩行是合法的 Mermaid 註解,不影響畫出來的圖,但**它是寫給填的人看的提示**,會原封不動留在產出裡
```
classDiagram
    %% 每個類別重複下面這一段
    class {{類別名稱}} {
        +{{方法名稱}}({{參數型別}} {{參數名稱}}) {{回傳型別}}
    }
    %% 相依別人的類別寫在左邊
    {{相依的類別}} --> {{被相依的類別}}
```

# Rule 4 [must] - 會變動的地方用填位符號標出
- 每一份產出都不一樣的內容寫成填位符號;每一份產出都一樣的內容照原樣寫
- 為什麼:沒標出來的地方,執行的人分不出是固定的還是某個案例留下來的,只會照抄

## good example
- 類別名稱、方法、關係的兩端**每次都不一樣,全部是填位符號**
```
classDiagram
    class {{類別名稱}} {
        +{{方法名稱}}({{參數型別}} {{參數名稱}}) {{回傳型別}}
    }
    {{相依的類別}} --> {{被相依的類別}}
```

## bad example
- 同一份骨架,但**類別名稱與關係留著某一次開發的內容**;執行的人會以為每張圖都要有 `OrderService`
```
classDiagram
    class OrderService {
        +{{方法名稱}}({{參數型別}} {{參數名稱}}) {{回傳型別}}
    }
    OrderService --> InventoryChecker
```

## good example
- 邊界:`classDiagram` 與方法前面的 `+` **每一份產出都一樣,所以照原樣寫**
```
classDiagram
    class {{類別名稱}} {
        +{{方法名稱}}({{參數型別}} {{參數名稱}}) {{回傳型別}}
    }
```

## bad example
- 邊界:把固定的兩處也挖成填位符號,看起來更有彈性,但**執行的人得去決定本來不該由他決定的事**,可能畫成別種圖、列出 private 成員
```
{{圖的種類}}
    class {{類別名稱}} {
        {{可見度}}{{方法名稱}}({{參數型別}} {{參數名稱}}) {{回傳型別}}
    }
```

# Rule 5 [should] - 填位符號寫成 `{{名稱}}`
- 填位符號用兩層大括號包住名稱
- 那個格式本身就用得到 `{{ }}` 時,換成那個格式裡不會出現的記法,整份骨架都用換過的那一種
- 為什麼:`{{ }}` 在多數格式裡沒有別的意思,一眼認得出哪裡還沒填;`<名稱>` 這類記法在 Markdown 預覽裡會被當成 HTML 標籤而消失,也會撞到 Mermaid 的 `<<…>>`

## good example
- 兩個填位符號**都是 `{{名稱}}`**,和 Mermaid 自己的 `<<…>>` 分得開
```
class {{類別名稱}} {
    <<{{新增、修改或既有}}>>
}
```

## bad example
- 同一段骨架,但**用 `<名稱>`**;第二行變成三層角括號,分不出哪幾個是 Mermaid 的、哪幾個是填位符號
```
class <類別名稱> {
    <<<新增、修改或既有>>>
}
```

## good example
- 邊界:這份骨架是 Hugo 的版型,`{{ .Title }}` 是要原樣留在產出裡的固定內容,**有正當理由不用 `{{ }}`,所以整份改用 `[[名稱]]`**
```
<article class="[[文章類型的 class 名稱]]">
  <h1>{{ .Title }}</h1>
  <div class="[[內文區塊的 class 名稱]]">{{ .Content }}</div>
</article>
```

## bad example
- 邊界:同一份版型仍照預設寫成 `{{名稱}}`;記法沒有錯,但**執行的人分不出哪個 `{{ }}` 是 Hugo 的、哪個是要填的**
```
<article class="{{文章類型的 class 名稱}}">
  <h1>{{ .Title }}</h1>
  <div class="{{內文區塊的 class 名稱}}">{{ .Content }}</div>
</article>
```

# Rule 6 [must] - 填位符號的名稱說明要填什麼
- 名稱寫出那個位置要放的內容,只讀名稱就知道該填什麼
- 能填的只有固定幾種時,把選項寫進名稱
- 為什麼:〈骨架整個檔案就是樣板〉讓骨架裡沒有地方放說明,名稱是唯一能告訴執行的人「這裡填什麼」的地方

## good example
- 四個名稱**各自說出要填的是什麼**
```
+{{方法名稱}}({{參數型別}} {{參數名稱}}) {{回傳型別}}
```

## bad example
- 同一行,但**名稱只是代號**;執行的人得去對範例,才猜得出四個位置各是什麼
```
+{{A}}({{B}} {{C}}) {{D}}
```

## good example
- 邊界:這個位置只能填三種,**三種都寫在名稱裡**
```
class {{類別名稱}} {
    <<{{新增、修改或既有}}>>
}
```

## bad example
- 邊界:名稱看得懂是在標狀態,但**有哪幾種可以填沒有寫**;執行的人會自己發明 `<<調整>>`、`<<重構>>`
```
class {{類別名稱}} {
    <<{{狀態}}>>
}
```

# Rule 7 [must] - 範例是骨架填完填位符號的樣子
- 範例的每一行都對得回骨架的某一行,差別只在每個填位符號都換成了具體內容
- 骨架裡的一段可以在範例裡重複多次,例如一個類別的區塊寫成兩個類別
- 為什麼:執行的人是對著範例學「填完長什麼樣子」的;範例多出骨架沒有的東西,他不知道該信哪一個

## good example
- 範例的**每一行都對得回骨架**:類別區塊重複了兩次,關係那一行出現一次
```
templates/class-diagram.mmd
  classDiagram
      class {{類別名稱}} {
          +{{方法名稱}}({{參數型別}} {{參數名稱}}) {{回傳型別}}
      }
      {{相依的類別}} --> {{被相依的類別}}

templates/class-diagram.example.mmd
  classDiagram
      class OrderService {
          +placeOrder(Cart cart) Order
      }
      class InventoryChecker {
          +isAvailable(Cart cart) bool
      }
      OrderService --> InventoryChecker
```

## bad example
- 同一份骨架,但**範例多了一行 `note for`**;骨架裡沒有這一行,執行的人不知道職責到底要不要寫
```
templates/class-diagram.mmd
  classDiagram
      class {{類別名稱}} {
          +{{方法名稱}}({{參數型別}} {{參數名稱}}) {{回傳型別}}
      }
      {{相依的類別}} --> {{被相依的類別}}

templates/class-diagram.example.mmd
  classDiagram
      class OrderService {
          +placeOrder(Cart cart) Order
      }
      class InventoryChecker {
          +isAvailable(Cart cart) bool
      }
      note for InventoryChecker "判斷購物車裡的商品庫存夠不夠"
      OrderService --> InventoryChecker
```

## good example
- 邊界:`InventoryChecker` 有兩個方法,骨架只寫了一行方法;**方法那一行重複了,但每一行仍對得回骨架**(骨架同上,只列範例)
```
classDiagram
    class OrderService {
        +placeOrder(Cart cart) Order
    }
    class InventoryChecker {
        +isAvailable(Cart cart) bool
        +reserve(Cart cart) Reservation
    }
    OrderService --> InventoryChecker
```

## bad example
- 邊界:同一份範例只把箭頭換成 `..>`,看起來只是選了另一種關係,但**骨架裡的 `-->` 是固定內容、不是填位符號**,這一行對不回骨架
```
classDiagram
    class OrderService {
        +placeOrder(Cart cart) Order
    }
    class InventoryChecker {
        +isAvailable(Cart cart) bool
        +reserve(Cart cart) Reservation
    }
    OrderService ..> InventoryChecker
```
