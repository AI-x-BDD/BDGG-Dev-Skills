# Rule 1 [must] - 任務指示檔以 `-p "$(cat 檔)"` 傳入
- 任務指示先存成檔,調用時用 `-p "$(cat <指示檔路徑>)"` 把全文當成 `-p` 的引數
- 禁止 `-p - < 檔`,也禁止把指示內容直接打在命令列
- 為什麼:agy 1.3.2 的 `-p` 把後面那個引數當成指示本身,不讀 stdin;`-p - < 檔` 會讓 agy 只收到一個 `-`,exit 0 卻沒有做事。把內容直接打在命令列,引號、換行與 `$` 會先被 shell 改掉

## good example
- 指示檔的全文**由 `"$(cat …)"` 展開成 `-p` 的引數**,agy 收到的就是檔案裡的內容
```bash
agy -p "$(cat /tmp/task_prompt.md)" --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/agy.json 2> /tmp/agy.err; echo $? > /tmp/agy.exit
```

## bad example
- 同一份指示檔,但**用 `-p -` 加 stdin 重導向**;agy 收到的指示只有一個 `-`,exit 0,工作目錄沒有任何變更
```bash
agy -p - --add-dir /project --mode accept-edits --output-format json --print-timeout 30m < /tmp/task_prompt.md > /tmp/agy.json 2> /tmp/agy.err; echo $? > /tmp/agy.exit
```

## good example
- 邊界:指示只有兩行,看起來不值得另存一個檔;**仍然先存成檔再用 `"$(cat …)"` 傳入**
```bash
# /tmp/task_prompt.md 的內容:
#   建立通知服務：process_event
#   請注意變數與引號
agy -p "$(cat /tmp/task_prompt.md)" --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/agy.json 2> /tmp/agy.err; echo $? > /tmp/agy.exit
```

## bad example
- 邊界:同樣兩行指示,因為短就**直接打在命令列**;`\n` 不會變成換行,內容裡一有引號或 `$` 就會先被 shell 改掉
```bash
agy -p "建立通知服務：process_event\n請注意變數與引號" --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/agy.json 2> /tmp/agy.err; echo $? > /tmp/agy.exit
```

# Rule 2 [must] - 指定工作目錄與模式
- 調用 `agy` 時必須使用 `--add-dir <dir>` 明確指定工作目錄路徑，並指定 `--mode accept-edits`
- 為什麼:未明確指定工作目錄或模式可能導致 agent 權限不足無法寫入目錄，或進入純規劃模式未實際產生代碼改動

## good example
- 明確指定 `--add-dir` 與 `--mode accept-edits`
```bash
agy -p "$(cat /tmp/task_prompt.md)" --add-dir /home/user/repo --mode accept-edits --output-format json --print-timeout 30m > /tmp/agy.json 2> /tmp/agy.err; echo $? > /tmp/agy.exit
```

## bad example
- 缺少工作目錄與模式設定，預設環境可能限制寫入或未套用編輯
```bash
agy -p "$(cat /tmp/task_prompt.md)" --output-format json --print-timeout 30m > /tmp/agy.json 2> /tmp/agy.err; echo $? > /tmp/agy.exit
```

# Rule 3 [must] - 輸出寫成 JSON、stderr 與結束碼三個紀錄檔
- 調用一律帶 `--output-format json`;stdout 重導向到 `agy.json`、stderr 重導向到 `agy.err`,指令最後接 `; echo $? > agy.exit` 把結束碼寫進 `agy.exit`;三個檔和任務指示檔放在同一個資料夾
- 為什麼:逾時與權限中止時 agy 回報的 `status` 都是 `SUCCESS`,回覆是空的或只有半句;要靠 JSON 的 `denied_actions` 與 stderr 的那一行才分得出是哪一種,文字模式只留下一個空的 stdout。`agy.exit` 出現才代表 agy 真的結束了;背景執行時太早去讀,`agy.json` 還是空的,會被當成失敗

## good example
- stdout、stderr 與結束碼**各寫進和指示檔同一個資料夾的 `agy.json`、`agy.err`、`agy.exit`**
```bash
agy -p "$(cat /tmp/task/task_prompt.md)" --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

## bad example
- 同一次調用,但**沒有帶 `--output-format json`,輸出也沒有存檔**;agy 被切掉的時候畫面上什麼都沒有,看不出是逾時、被拒還是它真的沒有回覆
```bash
agy -p "$(cat /tmp/task/task_prompt.md)" --add-dir /project --mode accept-edits --print-timeout 30m
```

## good example
- 邊界:stderr 平常是空的,看起來不值得存;**仍然寫進 `agy.err`**
```bash
agy -p "$(cat /tmp/task/task_prompt.md)" --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

## bad example
- 邊界:同一次調用,JSON 有存,但**stderr 用 `2> /dev/null` 丟掉**;逾時的那一行 `print timeout after … with turn in progress` 只寫在 stderr,JSON 裡仍然是 `SUCCESS`
```bash
agy -p "$(cat /tmp/task/task_prompt.md)" --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/task/agy.json 2> /dev/null; echo $? > /tmp/task/agy.exit
```

## good example
- 邊界:這次是前景執行,指令跑完就知道結束了,看起來不需要結束碼檔;**仍然接上 `; echo $? > agy.exit`**
```bash
agy -p "$(cat /tmp/task/task_prompt.md)" --add-dir /project --mode accept-edits --output-format json --print-timeout 5m > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

## bad example
- 邊界:同一次調用,但**沒有寫 `agy.exit`**;判定調用結果時沒有東西可以證明 agy 已經結束,讀到的可能是寫到一半的 `agy.json`
```bash
agy -p "$(cat /tmp/task/task_prompt.md)" --add-dir /project --mode accept-edits --output-format json --print-timeout 5m > /tmp/task/agy.json 2> /tmp/task/agy.err
```

# Rule 4 [must] - 一律指定時限,超過指令工具上限就放背景
- 調用一律帶 `--print-timeout`,值是使用者指定的時限;使用者沒有指定就用 `30m`
- 這個值超過呼叫端指令工具的時限(例如前景指令上限 10 分鐘)時,把整條指令放到背景執行,等 `agy.exit` 出現才算結束,再讀紀錄檔;不把值壓低去配合那個上限
- 為什麼:時限一到 agy 會直接切掉還在跑的回合,回覆是空的,改到一半的檔留在工作目錄;實測同一個任務跑了 7 分 45 秒與 8 分 33 秒,時限壓在 9 分鐘,第三次稍慢就被切掉,3 個檔改到一半

## good example
- 使用者沒有指定時限,呼叫端的前景指令上限是 10 分鐘;**帶 `--print-timeout 30m`,整條指令放到背景執行**
```bash
# 背景執行,等 agy.exit 出現後再讀 agy.json 與 agy.err
agy -p "$(cat /tmp/task/task_prompt.md)" --add-dir /project --mode accept-edits --output-format json --print-timeout 30m > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

## bad example
- 同一次調用,但**為了塞進 10 分鐘的前景上限,把時限壓成 `9m`**;任務跑到第 9 分鐘就被切掉
```bash
# 前景執行
agy -p "$(cat /tmp/task/task_prompt.md)" --add-dir /project --mode accept-edits --output-format json --print-timeout 9m > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

## good example
- 邊界:使用者指定時限 5 分鐘,沒有超過 10 分鐘的前景上限;**照使用者給的 `5m`,前景執行**
```bash
# 前景執行
agy -p "$(cat /tmp/task/task_prompt.md)" --add-dir /project --mode accept-edits --output-format json --print-timeout 5m > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```

## bad example
- 邊界:同一個情況,覺得小任務很快就回來,就**不帶 `--print-timeout`**;agy 預設會一直等到回合結束,卡住的時候沒有東西會讓它停下來
```bash
# 前景執行
agy -p "$(cat /tmp/task/task_prompt.md)" --add-dir /project --mode accept-edits --output-format json > /tmp/task/agy.json 2> /tmp/task/agy.err; echo $? > /tmp/task/agy.exit
```
