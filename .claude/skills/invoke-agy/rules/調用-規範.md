# Rule 1 [must] - 任務指示檔以 `-p "$(cat 檔)"` 傳入
- 任務指示先存成檔,調用時用 `-p "$(cat <指示檔路徑>)"` 把全文當成 `-p` 的引數
- 禁止 `-p - < 檔`,也禁止把指示內容直接打在命令列
- 為什麼:agy 1.3.2 的 `-p` 把後面那個引數當成指示本身,不讀 stdin;`-p - < 檔` 會讓 agy 只收到一個 `-`,exit 0 卻沒有做事。把內容直接打在命令列,引號、換行與 `$` 會先被 shell 改掉

## good example
- 指示檔的全文**由 `"$(cat …)"` 展開成 `-p` 的引數**,agy 收到的就是檔案裡的內容
```bash
agy -p "$(cat /tmp/task_prompt.md)" --add-dir /project --mode accept-edits
```

## bad example
- 同一份指示檔,但**用 `-p -` 加 stdin 重導向**;agy 收到的指示只有一個 `-`,exit 0,工作目錄沒有任何變更
```bash
agy -p - --add-dir /project --mode accept-edits < /tmp/task_prompt.md
```

## good example
- 邊界:指示只有兩行,看起來不值得另存一個檔;**仍然先存成檔再用 `"$(cat …)"` 傳入**
```bash
# /tmp/task_prompt.md 的內容:
#   建立通知服務：process_event
#   請注意變數與引號
agy -p "$(cat /tmp/task_prompt.md)" --add-dir /project --mode accept-edits
```

## bad example
- 邊界:同樣兩行指示,因為短就**直接打在命令列**;`\n` 不會變成換行,內容裡一有引號或 `$` 就會先被 shell 改掉
```bash
agy -p "建立通知服務：process_event\n請注意變數與引號" --add-dir /project --mode accept-edits
```

# Rule 2 [must] - 指定工作目錄與模式
- 調用 `agy` 時必須使用 `--add-dir <dir>` 明確指定工作目錄路徑，並指定 `--mode accept-edits`
- 為什麼:未明確指定工作目錄或模式可能導致 agent 權限不足無法寫入目錄，或進入純規劃模式未實際產生代碼改動

## good example
- 明確指定 `--add-dir` 與 `--mode accept-edits`
```bash
agy -p "$(cat /tmp/task_prompt.md)" --add-dir /home/user/repo --mode accept-edits
```

## bad example
- 缺少工作目錄與模式設定，預設環境可能限制寫入或未套用編輯
```bash
agy -p "$(cat /tmp/task_prompt.md)"
```
