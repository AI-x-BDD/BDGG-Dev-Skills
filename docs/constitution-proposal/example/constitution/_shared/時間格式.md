# Rule 1 [must] - 時間點一律帶時區,名稱以 at 結尾
- API(OpenAPI、AsyncAPI):表示時間點的欄位名稱以 `At` 結尾,`type: string`、`format: date-time`(RFC 3339,帶時區);不用 Unix timestamp
- 資料庫(DBML):表示時間點的欄位名稱以 `_at` 結尾,型別 `timestamptz`;不用 `timestamp`、`datetime` 或整數
- 只有日期、沒有時刻的欄位(生日、營業日)不適用本條
- 為什麼:API 與資料庫各自決定時間格式,實作的人就得在每一層猜時區;跨夏令時或跨時區部署時,沒帶時區的那一份會整批錯一小時

## good example
- 同一個時間點在 API 與資料庫**各自照自己的命名慣例,但都帶時區**
```yaml
# OpenAPI
paymentExpiresAt:
  type: string
  format: date-time
```
```
// DBML
payment_expires_at timestamptz [not null, note: '建立後 15 分鐘']
```

## bad example
- 同一個時間點,**API 用 Unix 秒數、資料庫用不帶時區的 `timestamp`**;兩邊對不起來,也看不出是哪個時區
```yaml
# OpenAPI
paymentExpiresAt:
  type: integer
  description: Unix timestamp
```
```
// DBML
payment_expires_at timestamp [not null]
```
