# 自己做出 Skill Engineering，再用它優化道館一的三支 Skills

你在第二章看見了水球老師如何一步一腳印地幹出整套 `/skill-engineering` orchestrator。

影片中水球老師的示範可不是一步登天地把完整的 `/skill-engineering` 幹出來，而是從 Skill 的四個部位開始（稱每個小部位為一個 skill primitives），帶你依序做出 Form Skills、Deriver Skills，最後再把它們組合成一支 orchestrator。

本道館要請你依照影片的方法，自己練習一次這種「由下而上」的建造流程，從中感受一下分割擊破的威力。

本道館共有兩題：

1. 實作七支 skill primitives，再把它們組合成 `/skill-engineering`（技能工程）。
2. 使用自己做出的 `/skill-engineering`（技能工程），優化道館一做出的三支 Skills。

## 第一題：實作七支 skill primitives 與一支 orchestrator

請依照第二章影片的 workshop 順序，完成以下八支 Skills。

### 第一支：`/skill-form-sop`（SOP 格式把關）

這支 Skill 負責把關每一支 Skill 的 SOP section。它要讓 Agent 知道一份 SOP 應該如何分段、每個步驟要寫到什麼程度，以及怎樣才算是可以實際執行的流程。

### 第二支：`/skill-form-rule`（規則格式把關）

這支 Skill 負責把關 Rule File。它要定義一條規則應該包含什麼、如何使用 Must／Should／May 表示規則強度，以及如何為規則提供 Good Example 與 Bad Example。

### 第三支：`/skill-derive-rule`（規則展開提取）

這支 Skill 會讀取一支已經寫好 SOP 的 Skill，選出其中一個需要更多規則的步驟，把該步驟展開成獨立且按需載入的 Rule File，再回頭修改原本的 SOP，寫清楚什麼時候要讀取這份 Rule File。

### 第四支：`/skill-form-template`（樣板格式把關）

這支 Skill 負責把關 Template。它要規定填位符號的寫法，以及每一份樣板如何使用「骨架＋範例」兩個檔案互相配對。

### 第五支：`/skill-derive-template`（樣板展開提取）

這支 Skill 會讀取一支已經寫好 SOP 的 Skill，找出其中一個需要固定輸出格式的步驟，把輸出格式展開成 Template 的骨架與範例，再回頭修改原本的 SOP，寫清楚讀取與使用 Template 的時機。

### 第六支：`/skill-form-script`（腳本格式把關）

這支 Skill 負責把關 Python Script。它要讓每一支腳本只有一個清楚的自動化目的，並寫清楚執行方式、第三方依賴、Inputs 與 Outputs。

### 第七支：`/skill-derive-script`（腳本展開提取）

這支 Skill 會讀取一支已經寫好 SOP 的 Skill，判斷其中的重複操作、格式轉換或機械檢查是否適合交給 Python Script。適合時，它要建立腳本，再回頭修改原本的 SOP，讓該步驟清楚委派腳本執行。

### 第八支：`/skill-engineering`

前面七支是 skill primitives。最後請把它們組合成一支 orchestrator：`/skill-engineering`。

`/skill-engineering` 至少要能處理兩種任務：

- 創建一支新的 Skill。
- 優化一支既有的 Skill。

執行時，它要先使用 `/skill-form-sop`（SOP 格式把關）建立或整理 SOP，再逐步判斷每一個 SOP Step 是否需要展開 Rule、Template 或 Script。需要時，應呼叫對應的 Deriver Skill；建立或修改這些檔案時，應由對應的 Form Skill 把關。

優化既有 Skill 時，不要看到結果不好就直接重寫。請先確認實際發生的問題、原本預期的結果，以及造成差異的根因，再決定要修改 SOP、Rule、Template、Script，或它們之間的組合方式。

### 第一題完成條件

請確認你已經完成：

- 七支 skill primitives 的完整 Skill 資料夾。
- 一支可以調度前面七支 Skills 的 `/skill-engineering`。
- 每一支 Skill 都有清楚的使用時機與職責，不會和相鄰的 Skill 做同一件事。
- `/skill-engineering` 可以實際完成一次「創建 Skill」與一次「優化 Skill」。
- 你能說明每一支 primitive 負責什麼，以及 `/skill-engineering` 如何組合它們。

## 第二題：優化道館一做出的三支 Skills

請使用你在第一題做出的 `/skill-engineering`，逐一優化道館一完成的三支 Skills：

- `/git-conventional-commit`（慣例式提交）
- `/trunk-based-development`（主幹式開發）
- `/double-diamond-principle`（雙鑽石原則）

將三支 skill 都改寫成 `/skill-engineering` 模組化的格式，然後去拜讀一下每個 skill 的 SOP 和 rules，都優化完畢後即算完成。

## 道館二完成條件

請準備以下內容，作為你完成道館二的證據：

- 所有 skills 的 skill package。
- 你自己做出的 `/skill-engineering` skill package。
- `/skill-engineering` 完成一次「創建 Skill」與一次「優化 Skill」的 git commit 紀錄。
- 道館一：三支 Skills 的優化前版本與優化後版本。
