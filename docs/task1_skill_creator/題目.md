# 立刻組合三支很有幫助的 Skills - git/TBD/雙菱形流程

你在第一章已經學會把「重複的步驟、流程或是概念、原則」，透過 Anthropic 官方的 `/skill-creator` 整理成 Skill。

本道館希望你多加練「請 AI 上網理解某個關鍵文獻的內容，以及延伸內容 -> 透過 `/skill-creator` 將其整理成 skill」的流程。

因此，接下來請你的 Agent 依照此流程分別創建三個 skills，然後再多多去試試看這三個 skills 有沒有用。

> 謎之聲：你當然也可以直接把這作業餵給 Agent... 看看他會不會一次全部做完...

## 第一部分：研究三個主題 -> 創建三個 skills

請 Agent 分別研究以下三個主題：

- `/git-conventional-commit`（慣例式提交）

  官方來源：[Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/)

- `/trunk-based-development`（主幹式開發）

  官方來源：[Trunk Based Development](https://trunkbaseddevelopment.com/)

- `/double-diamond-principle`（雙鑽石原則）

  官方來源：[Design Council — Double Diamond](https://www.designcouncil.org.uk/resources/framework-for-innovation/)

每一個主題都要完成以下內容：

1. 先讀完指定連結，再沿著網站中的相關頁面繼續查資料。
2. 整理這個主題的關鍵字、方法論、執行步驟、規則、適用條件與例外。
3. 保留資料來源，讓其他人可以回到原始內容核對。
4. 使用 `/skill-creator`（技能建立），把整理結果寫成一支可以實際使用的 Skill。

最後要得到三支可以分別啟用的 Skill：

- `/git-conventional-commit`（慣例式提交）
- `/trunk-based-development`（主幹式開發）
- `/double-diamond-principle`（雙鑽石原則）

## 第二部分：把三支 Skill 一起用在同一個專案

選一個你想開發的小型軟體專案，把需求拆成五到八個功能。每一次只開發一個功能，連續下達五到八次開發要求。

每次開發前，先依序啟用：

1. `/double-diamond-principle`（雙鑽石原則）
2. `/git-conventional-commit`（慣例式提交）
3. `/trunk-based-development`（主幹式開發）

接著輸入：

```text
請幫我開發 <把需求講一講>
```

把 `<把需求講一講>`（這一次的功能需求）換成這一次要完成的一個功能。下一次再換成下一個功能，直到同一個專案完成五到八個功能。

## 你要觀察什麼

如果 Agent 有遵循三支 Skill 的原則，你應該會看到：

- 開發前先理解使用者與問題、收斂這次要做的範圍，提出可能做法，選定做法後先用小範圍測試；取得新資訊時，會回頭修正前面的判斷。
- 每次只做一個足夠小的功能，使用 trunk 或短期 branch，整合前先跑測試，並讓 trunk 維持可以執行與發布；尚未完成的較長變更會使用 feature flag 或 branch by abstraction。
- 不相關的變更會拆開提交；每次提交都使用 Conventional Commits 的格式、正確的 type 與簡短描述，破壞相容性的變更會明確標示。
- 每次功能完成後，Agent 都能簡短指出這次如何使用 Double Diamond、測試結果、branch 與整合狀態，以及實際使用的 commit message。

## 完成條件

請準備以下內容，作為你完成這座道館的證據：

- 三支 Skill 的完整資料夾。
- 同一個小型軟體專案完成五到八個功能後所有 git commits 紀錄。
- 你（人類）下去觀察：哪些原則有被遵循，哪些沒有，以及你從哪一個實際結果看出來，有沒有優化空間？
